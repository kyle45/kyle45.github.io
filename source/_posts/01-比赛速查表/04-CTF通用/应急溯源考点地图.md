# 应急溯源考点地图

> **切入角度：出题者会把考点藏在哪里**
> 配套：`01-流量分析应急溯源手册.md`（工具与操作）
> 本篇讲**地图**，`01` 讲**工具**

---

## 0. 总纲：出题者只做三件事

任何一道应急溯源题，出题者的动作都逃不出这三个：

| 动作 | 做了什么 | 你要做的 |
|---|---|---|
| **埋点** | 把答案放在某个位置 | 找对位置 |
| **串联** | 线索 A 指向线索 B | 顺着往下追 |
| **干扰** | 放假线索、放"接近但不正确"的值 | 排除 |

**所以解题的本质是**：把检材按「**出题者可能埋点的层**」过一遍，而不是漫游。

---

## 1. 八个埋点层（从最容易被看到 → 最容易被漏掉）

### 第 1 层：命令历史（最直白）

**出题者最爱这里。** 因为攻击者的操作链能被完整还原，不用绕弯。

| 位置 | 说明 |
|---|---|
| `~/.bash_history` | Linux，最直接 |
| `/home/*/.bash_history` | **不止当前用户** —— 常分散在多个用户家目录 |
| `/root/.bash_history` | 提权后的操作在这 |
| **`ConsoleHost_history.txt`** | Windows PowerShell 历史，路径：`%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\` |
| `.zsh_history`、`.mysql_history`、`.python_history` | 其他 shell/程序的 |

> **埋点手法**：把操作**拆到不同用户**的历史里。`www-data` 里只有 webshell 上传，`root` 里才有提权和横向。

### 第 2 层：落地文件（临时目录是重灾区）

| 位置 | 说明 |
|---|---|
| `/tmp`、`/var/tmp`、`/dev/shm` | Linux 三件套，**隧道工具和木马最爱** |
| `%TEMP%`、`%APPDATA%`、`C:\Users\Public\` | Windows |
| Web 目录 | webshell |
| 下载目录、桌面 | 社工投递 |
| **`$Recycle.Bin`** | 删除的往往才是真相 |
| 隐藏文件 / `.` 开头的文件 | 隐藏木马 |

> **埋点手法**：改名的木马（`svchost.exe` 放在 `C:\Users\Public\`）、伪装成图片（改扩展名）、文件名反向暗示。

### 第 3 层：系统日志

**Linux**

| 文件 | 记什么 |
|---|---|
| `/var/log/auth.log` / `secure` | 登录、sudo、**爆破** |
| `/var/log/nginx/access.log`、`apache2/access.log` | **攻击者 IP、webshell、注入 payload** |
| `/var/log/nginx/error.log` | 失败尝试、路径探测 |
| `/var/log/wtmp`、`btmp`、`lastlog` | 登录记录（`last` / `lastb` 读） |
| `/var/log/messages`、`syslog` | 系统事件 |
| `~/.bash_history` | 见第 1 层 |

**Windows 事件 ID（背下来）**

| ID | 含义 |
|---|---|
| **4624** | 登录成功 |
| **4625** | 登录失败（爆破） |
| **4720** | **创建用户** ← 找隐藏账户 |
| 4722 / 4726 | 启用 / 删除用户 |
| 4688 | 进程创建 |
| **7045** | **服务安装** ← 持久化 |
| **4104** | PowerShell 脚本块 ← 能看到执行内容 |
| **1102** | **日志被清空** ← 这本身是线索！ |

> **埋点手法**：
> - **日志轮转** —— 答案在 `.1`、`.2`、`.gz` 后缀的副本里（`/var/log/*.log.1`）
> - **只留"正常记录"** —— 爆破成功的 200 混在几百条 401 里
> - **清空日志**（1102）—— 让你去别处找

### 第 4 层：文件元数据（不看内容，看属性）

**这一层最容易被漏，也最常出题。**

| 属性 | 考什么 |
|---|---|
| **时间戳（MACB）** | **网页被篡改时间、木马落地时间、文件最后修改时间** ← 高频 |
| **文件大小** | 异常大（隐写、附加数据） |
| **文件哈希** | 常直接作为答案：`flag{MD5}` |
| **文件权限** | SUID、异常权限 |
| **扩展名 vs 真实类型** | 改名的木马（`file` 一看便知） |
| PE 编译时间戳 | 木马生成时间 |
| **Office 文档元数据** | 作者、最后保存者 ← 钓鱼题常考 |
| 图片 EXIF | 拍摄设备、GPS |

> **工具**：`stat` / `ls -la --time-style=full-iso`、`Autopsy`、`exiftool`
> **埋点手法**：**用时间线还原顺序**（题目问"第一次/最后一次"），或故意制造时间戳矛盾让你发现 anti-forensics。

### 第 5 层：网络层

| 检材 | 找什么 |
|---|---|
| **流量包（pcap）** | 攻击者 IP、C2、上传的木马、webshell 连接、反弹 shell、**被窃文件** |
| **DNS 日志/查询** | DNS 隧道、dnslog 外带 |
| 连接记录 | `netstat -antp` / `ss -antp`（含 TIME_WAIT） |
| 防火墙/代理日志 | 出站连接、跳板机 |
| 中间件日志 | 访问记录 |

> **埋点手法**：
> - **答案在"最后一个包"**（如真题：最后一个 HTTP 响应 = 被下载的 docx）
> - **把关键请求混在大量正常请求里**（SQL 盲注爆破几千个请求）
> - **不给你回显**，只能从流量特征推（GitLab RCE 无回显）

### 第 6 层：内存（最"深"，断电就没）

| 找什么 | 说明 |
|---|---|
| 进程列表 | 隐藏进程、**异常父进程** |
| **`netscan`** | **已经断开的连接也能看到** ← 关键 |
| `cmdline` | 进程完整命令行（矿池地址常在这） |
| 注册表 hive | 持久化、最近运行 |
| 剪贴板 | 复制的密码 |
| 浏览器历史 | 攻击者上过哪些站 |
| lsass | 明文凭据 |
| **已删除但还在内存里的文件** | `filescan` + `dumpfiles` |
| 注入的代码段 | 内存马 |

> **埋点手法**：把答案放在**磁盘上已经被删、但内存里还在**的地方。只用磁盘取证会漏掉。

### 第 7 层：应用层

| 位置 | 找什么 |
|---|---|
| Web 应用日志 | 业务层攻击 |
| 数据库日志 / binlog | 数据被拖的时刻和内容 |
| 应用配置 | 数据库凭据、密钥 |
| session 文件 | 会话劫持 |
| 邮件队列 / eml | 钓鱼邮件，`From` 头里是发送 IP |
| 业务数据本身 | 被窃数据的内容（常要算 MD5） |

### 第 8 层：编码与隐写（答案"不是明文"）

| 手法 | 处理 |
|---|---|
| **base64** | 反弹 shell 命令、邮件正文、配置 ← **最高频** |
| hex / 多层编码 | 逐层解 |
| 图片隐写 | LSB、附加数据、EXIF |
| 压缩包 | 伪加密、密码爆破、明文攻击 |
| **文件尾部附加数据** | `binwalk` / `tail -c` |
| 需要**写脚本批量提取** | SQL 盲注爆破、日志正则提取 ← **区分度在这** |

> **埋点手法**：**答案必须"算出来"** —— 解码、解密、拼接、算 MD5。这是拉开差距的地方。

## 2. ★ 最容易被漏掉的 10 个位置

**赛前把这张表背下来。**

| # | 位置 | 为什么容易漏 |
|---|---|---|
| 1 | **日志轮转副本**（`.1`、`.gz`） | 只看 `access.log`，忘了历史 |
| 2 | **非当前用户的家目录** | `history` 分散在 `/home/*/` 和 `/root/` |
| 3 | **`/var/spool/cron/crontabs/`** | 只知道 `/etc/cron*`，漏了 spool |
| 4 | **`/etc/passwd` 里 UID=0 的非 root 账户** | 只看用户名，没看 UID |
| 5 | **`$Recycle.Bin`** | 觉得"删了就没用了" |
| 6 | **`ConsoleHost_history.txt`** | 只知道 bash_history |
| 7 | **`netscan` 里已断开的连接** | 只看当前 `netstat` |
| 8 | **文件尾部附加数据** | 只看文件"内容" |
| 9 | **环境变量**（`env`、`/proc/<pid>/environ`、`~/.bashrc`） | 从不看这里 |
| 10 | **systemd user 级服务**（`~/.config/systemd/user/`、`.timer`） | 只看系统级 |

**加分项**：`/proc/<pid>/exe`（看真实二进制路径，绕过改名）、`/proc/<pid>/cwd`

## 3. 出题者的十种埋点手法

| # | 手法 | 例子 |
|---|---|---|
| 1 | **base64 包一层** | 反弹 shell 命令、邮件正文 |
| 2 | **放在"最不像"的地方** | 环境变量、注释里、文件尾 |
| 3 | **时间戳错位** | 要你用时间线还原顺序 |
| 4 | **改名 / 伪装** | `svchost.exe` 放 `C:\Users\Public\` |
| 5 | **反向命名** | 文件名诱导你忽略它 |
| 6 | **藏在正常记录里** | 爆破成功混在 401 里 |
| 7 | **多跳串联** | A 文件提到 B 服务 → B 日志里有 C 的 IP |
| 8 | **要求"算出来"** | 解码 / 解密 / 拼接 / 算 MD5 |
| 9 | **同型干扰** | 真木马 + 测试木马各一个 |
| 10 | **问"第一次/最后一次"** | 必须排序，不能只看一条 |

## 4. 问法 → 落点反查表（题目怎么问，就去哪找）

| 题目问 | 优先去 |
|---|---|
| 攻击者 IP | Web access.log → 流量 → auth.log |
| 木马文件名 / 路径 | 磁盘 → Web 目录 → 日志的上传记录 |
| 一句话木马密码 | 木马源码 → 流量 POST 参数 |
| 反弹 IP:端口 | **history** → 流量 → 配置文件 |
| 利用的漏洞 / CVE | 请求 payload → 日志 → 扫描器特征 |
| 创建的用户名 | auth.log → 事件 4720 → `/etc/passwd` |
| 持久化方式 | cron → 服务 → 注册表 → 计划任务 |
| **被窃文件名** | **流量下载响应** → 文件访问日志 |
| 矿池地址 | 进程 cmdline → 配置文件 → 流量 |
| 隐藏账户密码 | **`net user` 命令历史** → 内存 → 注册表 |
| 某个时间点 | 文件时间戳 → 日志时间戳 |
| 文件哈希 | 找到文件后 `md5sum` ← **注意题目要求大小写** |

## 5. 干扰项：出题者会怎么骗你

| 干扰 | 应对 |
|---|---|
| 假 flag / 测试文件（`test.php`、`1.php`） | 看**时间顺序**和**是否被真正使用** |
| 题目描述里的烟雾弹 | 只信检材，不信描述 |
| 多个相似 IP（多级跳板） | 分清"攻击者 → 跳板 → 目标"的链 |
| 被篡改的时间戳 | 交叉验证（日志 + 流量 + 元数据） |
| **日志被清空** | 这不是干扰，是**线索**（1102）→ 去别处找 |
| 编码内容里套错误答案 | 解到底再信 |
| 干扰进程（正常业务的大流量） | 看进程路径和父进程 |

## 6. 出题者视角自检（反过来想）

**如果我是出题人，这道题我会怎么埋？**

```
我要考"攻击者 IP"
  → 放在 access.log？太简单
  → 放流量里？要过滤才找得到 ✔
  → 那我在 access.log 里也放一堆扫描器的 IP 干扰 ✔

我要考"被窃文件"
  → 直接放文件名？太简单
  → 放流量下载响应里，还要从 Content-Disposition 或文件头判断 ✔
  → 再要求提交 MD5，逼你真把文件提取出来 ✔

我要考"持久化方式"
  → 放 crontab？常规
  → 放 systemd timer？更隐蔽 ✔
  → 再在 crontab 里放个假的 ✔
```

**核心规律**：**答案总在"需要动一下手才能拿到"的地方** —— 要么需要过滤/提取/解码，要么需要跨来源交叉验证。

## 7. 答题规范（丢分重灾区）

| 项 | 注意 |
|---|---|
| **格式** | 严格照题目。`flag{...}` 还是裸值？IP 带不带端口？ |
| **MD5** | **大小写**！题目常要求全小写 |
| **路径** | 绝对路径，`/` vs `\` 按题目 |
| **时间** | 格式、时区 |
| **IP** | 别漏小数点；分清内网/外网 |
| **多选题** | 别漏填 |
| **提交次数** | 常见限制 3 次 —— **先记全再提交** |

## 8. 快速上手流程（拿到检材的 15 分钟）

```
1. file 看每个附件真身（可能有文件分离）
2. 列出所有检材，按类型分组（流量/内存/磁盘/日志/文件）
3. 对每一类，按第 1 章的"八个埋点层"过一遍
4. 特别对照第 2 章"最容易被漏掉的 10 个位置"
5. 拿第 4 章反查表，对着题目逐条找
6. 需要批量提取 → 写脚本（pyshark / 正则）
7. 记下每条答案的**来源位置**（复核用）
```

> **记来源这一步很重要**：答题卡制、提交次数有限，回头复核时你需要知道每个答案是从哪来的。
