# 线下断网CTF/渗透赛 · 多层靶机备赛笔记

> 核心判断：这种"线下、断网、多层靶机"的赛制，出题思路通常有规律——重点不是考"能不能搜到一个现成EXP"，而是考**信息收集 → 漏洞判断 → 手工利用/改造 → 横向 → 权限提升 → 再发现**这一整条链。可以把它理解为一种"小型企业内网渗透"。

---

## 1. 第一层：入口

断网环境下，出题人如果直接放一个冷门1-day要求现场手搓，体验会比较差。所以更可能考察：

- Web常见漏洞：SQLi、文件上传、命令注入、SSRF、反序列化
- 弱口令 / 默认口令 / 凭据泄露
- 信息泄露 → 找到后台
- 简单的业务逻辑漏洞
- 已知但容易手工利用的漏洞
- 服务配置错误

**典型暴露端口示例：**

```
80    Web
22    SSH
3306  MySQL
8080  某管理系统
```

真正考点可能不是"找一个EXP"，而是通过 `nmap`、目录枚举、源码、配置文件慢慢判断出如下链条：

```
Web → 文件上传 → WebShell
        ↓
      配置文件
        ↓
    数据库密码
        ↓
       SSH
```

这种链条特别适合线下赛。

---

## 2. 第二层：凭据流动

这是多层靶机里非常值得重点准备的方向。

第一台拿到低权限之后，不一定马上给你一个提权漏洞，而是让你从机器里找：

- `/etc/passwd`
- `/home/*/`
- `.bash_history`
- `.env`
- `config.php`
- `application.yml`
- 数据库配置
- SSH key
- 备份文件
- 日志
- 脚本
- 定时任务

**典型凭据流动路径：**

```
userA
  ↓ 密码复用
server02
```

```
Web配置
  ↓
MySQL credential
  ↓
数据库
  ↓
另一套业务账号密码
  ↓
内网SSH
```

> **关键习惯：拿到Shell后不要急着找提权。** 这个习惯在线下多层赛里尤其重要。

---

## 3. 第三层：内网发现 / Pivot 

如果题目真的叫"多层靶机"，很可能存在这种拓扑：

```
             ┌──────────────┐
             │  Attack PC   │
             └──────┬───────┘
                    │
                  DMZ
                    │
             ┌──────▼───────┐
             │   Server A   │
             │  192.168.1.x │
             └──────┬───────┘
                    │
              内网 / 双网卡
                    │
             ┌──────▼───────┐
             │   Server B   │
             │  10.10.10.x  │
             └──────┬───────┘
                    │
             ┌──────▼───────┐
             │   Server C   │
             │  10.10.20.x  │
             └──────────────┘
```

这时候考的不是某个CVE，而是："**你有没有意识到这台机器是跳板。**"

拿到A后依次执行：

```bash
ip addr
ip route
arp -a
```

若发现：

```
eth0 → 192.168.1.0/24
eth1 → 10.10.10.0/24
```

则说明存在第二层网络，需要想办法进入。

线下赛甚至可能故意把外部攻击机和目标网络隔离，让你必须通过已有Shell做：

- SSH隧道
- SOCKS代理
- 端口转发
- 反向隧道
- 代理工具

> 因为比赛环境受限，纯手工SSH隧道这类基础技能建议优先掌握，不要把希望全押在某个现成工具上。

## 4. 手工利用能力

平时看到「Apache xxx RCE」，第一反应可能是搜GitHub / Exploit-DB。

线下断网后，思路要变成：**这个漏洞本质上为什么能RCE？我能不能自己构造请求？**

建议准备**漏洞原理 + 手工利用模板**，而不是一堆现成EXP。

### SQL注入

基本payload：
```sql
' OR 1=1--
```

UNION注入：
```sql
' UNION SELECT ...
```

盲注：
```sql
' AND SUBSTRING((...),1,1)='a'--
```

### 文件上传

检查点：文件类型 / 扩展名 / Content-Type / 解析器 / Web Server配置

### SSRF

```
http://127.0.0.1/
http://localhost/
http://内网IP/
```

### 命令注入

常用分隔符/构造：`;`、`&&`、`||`、`|`、`$()`、反引号

> 把EXP拆成「漏洞触发条件 + payload + 利用链」，线下会舒服很多。

## 5. 提权重点方向

### Linux（第一梯队）

- sudo
- SUID
- Capabilities
- Cron
- 可写脚本
- PATH劫持
- SSH key
- 历史命令
- 敏感配置

**常用枚举命令：**
```bash
sudo -l
find / -perm -4000 -type f 2>/dev/null
getcap -r / 2>/dev/null
crontab -l
```

排查思路：谁执行？以什么身份执行？脚本在哪里？脚本是否可写？调用的程序是否可控？环境变量是否可控？

### Windows

- 服务权限
- 弱服务配置
- 计划任务
- AlwaysInstallElevated
- Unquoted Service Path
- 注册表权限
- 凭据残留
- PowerShell
- Token / Privilege

## 6. 看似无用的信息，最后往往串起来

这类比赛特别喜欢埋线索，例如：

```
第一台: /var/www/html/backup.zip
  → 内含 db_backup.sql
  → 数据库中发现 admin / xxxx
  → 登录第二台Web后台
  → 后台功能可上传文件
  → 拿到 server02 Shell
  → server02 的 /etc/hosts 中发现:
      git.internal
      oa.internal
      db.internal
  → 继续横向...
```

看到以下类型信息都建议记下来：域名、IP、用户名、密码、Token、密钥、项目名、机器名、数据库名。

| 优先级 | 能力 |
|---|---|
| ★★★★★ | nmap / 端口服务识别 |
| ★★★★★ | Web手工漏洞利用 |
| ★★★★★ | Linux基础命令与权限分析 |
| ★★★★★ | 凭据/配置/源码信息搜集 |
| ★★★★★ | 内网发现 |
| ★★★★☆ | SSH / SOCKS / 端口转发 |
| ★★★★☆ | Linux提权 |
| ★★★★☆ | Windows提权 |
| ★★★★☆ | 数据库操作 |
| ★★★☆☆ | 常见漏洞原理与手工POC |
| ★★★☆☆ | 简单脚本现场改EXP |
| ★★☆☆☆ | 冷门CVE的现成EXP |

## 最重要的一点

不要把"多层靶机"理解成"一台机器一个漏洞"，更接近这样一条链：

```
入口
 ↓
低权限Shell
 ↓
本机信息搜集
 ↓
凭据 / 密钥 / 配置
 ↓
内网发现
 ↓
Pivot
 ↓
第二台
 ↓
新的漏洞/凭据
 ↓
横向
 ↓
提权
 ↓
最终目标
```

甚至可能出现更长的链条：

```
Web漏洞 → www-data → 配置泄露 → 普通用户 → SSH → 内网主机
   → 数据库 → 业务账号 → 另一台Windows → 域环境 → 最终Flag
```

**结论：** 与其花大量时间背"1000个EXP"，更划算的是准备一套**完全离线的渗透工具箱 + 常见漏洞手工利用速查表 + Linux/Windows提权枚举清单 + 内网Pivot方法**。
