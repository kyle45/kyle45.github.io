# 文件包含

### **1. **`**include_once()**`** 函数**

* **基本行为:**`include_once($file)` 函数在成功包含文件时默认返回 `1`，但如果文件中有 return，则返回 return 的值 。如果文件包含失败，它会产生一个警告并返回 `false`（不返回任何值到输出流）。
* **参数类型与执行行为:**
 * `.txt` / `.html` / `.xml`：文件内容会被直接输出。浏览器会根据文件类型渲染 `.html` 和 `.xml`。
 * **二进制文件：** 文件内容会被解释为文本并以乱码形式输出。
 * **包含 PHP 代码的非 **`**.php**`** 文件：** 即使文件后缀不是 `.php`，只要其中有 PHP 代码，`include_once()` 仍然会执行它。
* **示例:**
 * file\_to\_include.php:

```plain
<?php
  echo "This is the included file.";
?>
```

* include\_once 调用:

```plain
<?php
  $result = include_once("file_to_include.php");
  echo $result;
?>
```

```
- **最终输出:**`This is the included file.1` （`echo` 的内容在前，`include_once` 的返回值在后）。
```

### **2. **`**php://filter**`** 伪协议**

* **作用:**`php://filter` 是一种特殊的 PHP 伪协议，用于在文件包含时对数据流进行处理，而不会直接执行代码。
* **利用方式:**`file=php://filter/read=convert.base64-encode/resource=./flag.php`
 * `read=convert.base64-encode`：这是过滤器，将 `resource` 指定的文件内容进行 Base64 编码。
 * `resource=./flag.php`：这是要处理的目标文件。
* **优势:** 通过这种方式，我们可以通过 Base64 编码将原本不可见的源代码转化为可读取的字符串输出。

### **3. **`**preg_match()**`** 正则表达式**

* **preg\_match() 返回值是 1（匹配成功）/ 0（不匹配）/ false（正则语法错误）**
* **作用:** 用于在字符串中进行模式匹配。
* **语法:**`preg_match("/flag/i", $file)`
 * `/flag/`：是正则表达式，其中 `/` 是**定界符**，`flag` 是要匹配的字符串。
 * `i`：是**修饰符**，表示在匹配时忽略大小写（不区分 `flag`、`Flag`、`fLaG` 等）。

### \*\*4. 日志文件包含 \*\*

### \*\*\*\*

* **路径：**
 * **/var/log/nginx/access.log**
 * **...**
* **原理:** 许多 Web 服务器会将用户的 HTTP 请求信息（如 User-Agent、Referer 等）记录在日志文件中。攻击者可以通过修改这些请求头，在日志中写入 PHP 代码。
* **利用方式:**
 1. 找到日志文件路径，例如 `/var/log/nginx/access.log`。
 2. 在 HTTP 请求的 `User-Agent` 头中写入一句话木马，例如 `User-Agent: `。
 3. 使用 `include()` 或 `include_once()` 函数包含该日志文件。由于 `include()` 函数会把文件中的内容当作 PHP 代码执行，日志文件中的恶意代码就会被执行。
 4. 最后，使用像 **蚁剑** 这样的工具连接到服务器。
